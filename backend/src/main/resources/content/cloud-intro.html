산업혁명의 이해

산업혁명에 대해 이해해야 클라우드의 중요성을 알 수 있다! 혁명이라는 것은 결국 세상이 바뀐 것이다.

1차 산업혁명: 증기

  • 이전에는 가내수공업 형태였다.
  • 직물을 짜는 것을 자동화 → 공장이 생김 → 직원(사람)들이 많아짐 → 식당과 같은 가게들이 많이 생김 → 도시가 생김
  • 증기 기관차의 등장 → 무역 증가

2차 산업혁명: 전기

3차 산업혁명: 전자

  • 전자 계산기 → 서버-클라이언트 시대로 이어짐

→ 각 혁명마다 그때그때 관련된 사람들이 (직업적으로) 살아남았다.

4차 산업혁명: AI, 빅데이터, 클라우드, IoT

온프레미스와 클라우드

온프레미스(On-premise)

  • 서버-클라이언트 구조에서 서버에 해당한다.
  • 베어메탈(물리적인 저장 공간)을 직접 보유한다.
  • 한계점
    • 긴 조달 시간
    • 막대한 초기 비용
    • 낮은 자원 활용률

→ 클라이언트의 접속이 많아질 때를 대비하여 서버를 많이 확보(투자)하지만, 1년 내내 사용량이 많은 것은 아니므로 자원 활용률이 낮아진다.

예시: 아마존의 블랙 프라이데이 → 전 세계 사람들의 접속(1년 매출의 약 60%) → 서버를 대량 확보한다. 하지만 블랙 프라이데이가 끝나면 사용량이 급감 → 확보한 서버가 낭비된다.

👉 그렇다면 인터넷 상에서 서버를 확보하자! ⇒ 이 아이디어에서 아마존의 클라우드 서비스(AWS)가 유명해졌다.

클라우드(Cloud)

정의: 인터넷을 통해 액세스할 수 있는 서버와, 이러한 서버에서 작동하는 소프트웨어 및 데이터베이스.

클라우드의 핵심 특성:

  • 온디맨드 셀프 서비스 — 즉시 프로비저닝이 가능하다.
    • 프로비저닝(Provisioning): IT 인프라(서버, 스토리지, 네트워크 등)나 사용자 계정을 생성, 설정, 배포하여 즉시 사용할 수 있도록 준비하는 전체 과정.
  • 광대역 네트워크 접근 — 인터넷만 연결되어 있다면 어디서나 접속할 수 있다.
  • 자원 풀링 — 가상화를 통한 멀티테넌시를 제공한다.
    • 멀티 테넌시(Multi-tenancy): 단일 소프트웨어 인스턴스로 여러 고객(테넌트)에게 서비스를 제공하는 클라우드 아키텍처.
  • 신속한 탄력성 — 무한한 확장과 축소가 가능하다. 확장과 축소를 적절하게 하여 무한한 자원을 가진 것처럼 사용한다.
  • 측정된 서비스 — 서비스를 사용한 만큼만 값을 지불한다. → 스타트업에서 많이 사용한다.

2006년 AWS의 S3와 EC2 등장: 인터넷 상에서 자원을 빌려 쓸 수 있게 되었다.

클라우드를 사용하면 장점만 있을까?

온프레미스의 장점

  • 정보의 안정성 확보
    • 클라우드를 사용할 수 없는(사용하기 어려운) 분야: 금융, 의료 등

→ 특정 분야를 제외하면 클라우드를 사용하지 못할 이유가 없다.

클라우드를 사용했을 때 고려할 점

  • 클라우드는 곧 임대이므로 임대료를 계속 내야 한다.
    • 5년 이상 사용한다고 하면 비용 책정을 통해 사용 여부를 다시 고려해봐야 한다.
  • 규모의 경제가 되지 않는다.
    • 하드웨어(온프레미스)는 규모가 커지면 단가가 절감되고 지속적으로 가격이 인하된다.
    • 초기 투자 비용만 지불하면, 이후에는 추가 비용보다 수익이 더 커진다.

클라우드 서비스 모델의 이해(SPI 모델)

SPI 모델은 클라우드 서비스를 제공 범위에 따라 IaaS, PaaS, SaaS 세 가지로 구분한다.

IaaS(Infrastructure as a Service)

  • 서버의 기반 시설(인프라)을 제공한다.
  • 온프레미스 시스템을 클라우드로 이전하는 사람에게 적합하다.
  • OS(운영체제) 수준까지 제어해야 하는 개발팀(시스템 엔지니어)이 사용한다.
    • 예: 윈도우 운영체제의 컴퓨터에서 리눅스 환경 개발을 해야 할 때 사용한다.

PaaS(Platform as a Service)

  • 운영체제뿐 아니라 미들웨어, 런타임(실행 환경)까지 함께 제공한다. → 개발자가 많이 사용한다.
    • 코드 작성과 비즈니스 로직에만 집중할 수 있다.

SaaS(Software as a Service)

  • 완성된 소프트웨어 애플리케이션 자체를 인터넷을 통해 구독 형태로 사용한다.
  • 서비스를 사용만 하는 일반 사용자(사실상 모든 사람)가 대상이다.

서비스 비용은 그때그때, 서비스마다 다르다! 많이 제공한다고(PaaS) 해서 무조건 비싼 것은 아니다.

책임 공유 모델(Shared Responsibility)

각 서비스 모델(IaaS/PaaS/SaaS)은 서비스 레벨, 즉 사람이 직접 다뤄야 하는 부분이 어디까지인지가 서로 다르다. SaaS로 갈수록 사용자가 관리해야 하는 영역이 줄어들고, 공급자가 관리하는 영역이 늘어난다.

클라우드 배치 모델(Deployment Model)

  • AWS는 퍼블릭 클라우드(공공 클라우드)에 해당한다.
  • 회사의 기밀 문서 등을 위해 프라이빗(기업) 클라우드를 구축하기도 한다.
    • 공공기관(행정구역)에서도 사용한다. 하나의 사설 클라우드 내에서 행정 구역별로 공간을 할당하는 식이다.
  • 하이브리드 클라우드: 퍼블릭 클라우드와 프라이빗 클라우드들이 연결되어 있는 구조로도 존재한다(서로 다른 클라우드를 연동).
    • 각각의 클라우드는 사용법이나 규칙이 다르므로, 연동이 가능하도록 만든다.
  • 로컬 클라우드

클라우드의 핵심 기술

가상화(Virtualization)의 원리

가상화

정의: 물리적 하드웨어 자원을 소프트웨어적으로 추상화하여, 하나의 물리 장비 위에서 여러 개의 독립된 환경을 동시에 실행하는 기술.

하이퍼바이저(Hypervisor)

  • 물리 서버 위에서 여러 개의 가상 머신(VM, Virtual Machine)을 생성하고 관리하는 소프트웨어.
    • 각각의 VM은 독립된 컴퓨터처럼 동작하고 완전히 격리된다.
    • 예를 들면 오락실 게임기를 가상화한 것이 MAME 서비스다.
  • VMware가 사용법이 쉽고 성능이 좋다(최근 무료로 풀림).

컨테이너와 마이크로서비스(MSA)의 배경

  • 하이퍼바이저를 사용하면 가상의 컴퓨터(운영체제)가 각각 생성된다.
  • 만약 특정 운영체제가 아니라 운영체제 위에서 사용하는 서비스만 필요하다면, 필요할 때마다 가상 머신을 만드는 것은 너무 비효율적이다(용량이 매우 큼).

👉 그래서 컨테이너를 사용한다.

정의: OS를 공유하여 프로세스(서비스)만 격리하고, 어디서나 동일하게 실행되도록 하는 기술.

MSA(Microservices Architecture)

  • 쿠버네티스의 사용으로 서버 관리(생성, 삭제)가 용이해지면서, 각각의 서비스를 분리하는 방식이 제시되었다.
  • 서비스를 기능별로 독립된 소규모 서비스로 분리한다.
    • 각 서비스는 독립된 컨테이너로 패키징되어, 서로 API로 통신한다.
  • 독립적으로 개발, 배포, 확장할 수 있다.
  • 특정 서비스에 버그가 생겨도 다른 서비스에는 영향을 주지 않는다.

서버리스(Serverless)와 추상화

서버리스

정의: 개발자가 서버를 직접 관리할 필요가 없는 것(서버가 없다는 뜻이 아니다).

  • 비즈니스 로직 코드만 작성하면, 나머지(서버 프로비저닝, OS 관리, 스케일링, 패치)는 모두 클라우드 공급자가 처리하는 컴퓨팅 모델이다.
  • 엔드포인트만 제공하면, 요청과 응답을 처리하는 과정은 클라우드 공급자가 처리하는 방식이다.

서버리스의 장단점

장점

  • 서버 관리 불필요 → 개발자가 코드에만 집중할 수 있다.
  • 자동 스케일링 → 트래픽 급증에 자동으로 대응한다.
  • 실행 시간만 과금 → 요청이 없으면 비용이 0원이다.
  • 빠른 개발 및 배포 속도.

단점

  • 콜드 스타트(Cold Start): 처음 실행 시 함수를 불러오는 지연 시간이 발생한다.
  • 실행 시간 제한이 존재한다(AWS Lambda: 최대 15분).
  • 로컬 상태 저장이 불가능하다(무상태 설계 필수).
  • 공급자 의존성(Vendor Lock-in)이 심화된다.

데브옵스(DevOps)와 SRE

클라우드 환경에서 빠르고 안정적으로 소프트웨어를 만들고 운영하려면, 개발과 운영이 하나가 되어야 한다.

DevOps

정의: 개발(Dev)과 운영(Ops)이 하나의 팀으로 협력하는 방법론이자 문화.

  • 개발(Dev)
  • 운영(Ops)

CI/CD 파이프라인

  • CI(지속적 통합), CD(지속적 배포)를 의미한다.
  • 우리 부트캠프 과정에서는 거의 사용하지 않을 예정이다.

클라우드의 미래

엣지 컴퓨팅

  • 클라우드의 가장 큰 약점은 지연 시간(Latency)이다.
  • CPU와 GPU는 연산 방법이 다르다.
    • CPU(중앙 처리 장치): 수십억 개의 트랜지스터로 구성되어, 복잡한 논리 연산과 순차적 작업을 처리하는 컴퓨터의 두뇌.
    • GPU(그래픽 처리 장치): 수천 개의 작은 코어를 활용해 대규모 데이터를 병렬로 빠르게 처리하는 그래픽/AI 연산 특화 장치.

클라우드 개론 전체 요약

산업혁명의 흐름 속에서 4차 산업혁명의 핵심으로 등장한 클라우드는, 온프레미스의 한계(긴 조달 시간, 막대한 초기 비용, 낮은 자원 활용률)를 극복하기 위한 대안이다. 온디맨드 셀프 서비스, 광대역 네트워크 접근, 자원 풀링, 신속한 탄력성, 측정된 서비스라는 특성을 가지며, IaaS·PaaS·SaaS(SPI 모델)와 퍼블릭·프라이빗·하이브리드 배치 모델로 나뉜다. 가상화·컨테이너·MSA·쿠버네티스 같은 핵심 기술과 SDx, 보안 아키텍처(IAM, VPC, 제로 트러스트 등)를 기반으로 하며, 서버리스·DevOps·SRE·데이터/AI 생태계·거버넌스와 FinOps로 확장된다. 미래에는 엣지 컴퓨팅, AI 인프라, 지속 가능성, 양자 컴퓨팅 클라우드로 나아간다.
