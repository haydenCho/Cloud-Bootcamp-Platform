리눅스 기초 — 개념, 명령어, 네트워크

리눅스는 서버 환경에서 가장 널리 쓰이는 운영체제입니다. 클라우드 서버, 도커 컨테이너, 쿠버네티스 노드가 대부분 리눅스 위에서 동작하기 때문에, 기본 개념과 명령어에 익숙해지는 것이 이후 모든 실습의 기반이 됩니다. 이 단원에서는 리눅스의 탄생 배경과 핵심 구조부터, 파일·프로세스·권한·네트워크·텍스트 편집기까지 실무에서 자주 쓰는 명령어를 정리합니다.

리눅스란 무엇인가?

운영체제(OS)란?

운영체제는 컴퓨터의 부품(메모리, CPU, GPU, 하드디스크, 메인보드 등)을 좋은 성능으로 활용할 수 있도록 운영·관리해 주는 장치입니다.

리눅스의 탄생과 오픈소스

  • 리눅스 이전에 최초의 운영체제인 유닉스가 개발됨(나사가 의뢰하여 버클리대에서 개발). 서로 다른 컴퓨터끼리 신호를 주고받는 TCP/IP 기술이 여기서 함께 발전했고, 이후 유닉스는 다양한 갈래로 나뉘어 발전했습니다.
  • 리누스 토발즈가 개인 PC에서 쓸 수 있는 운영체제의 핵심 기능을 직접 만들어 인터넷에 무료로 공개했고, 이후 여러 사람이 기능을 추가하며 리눅스가 완성되었습니다. 이것이 오픈소스 방식입니다.
  • 기업들은 돈을 지불하고 상용 리눅스를 사용하기도 합니다. 문제가 발생했을 때 기술 지원을 받는 대가로 책임 비용을 내는 방식이며, 대표적으로 레드햇(Red Hat)이 있습니다.
  • 리눅스는 크게 레드햇(Red Hat) 계열과 데비안(Debian) 계열로 발전했습니다.
    • 데비안: 개발자와 클라우드 진영에서 많이 사용. 사용자 친화적이고 커뮤니티가 활발함.
    • 레드햇: 기업용 서버에서 많이 사용. 안정성이 강점.

CLI(Command Line Interface)

리눅스는 커맨드 라인과 명령어를 사용하는 방식이고, 윈도우는 마우스로 아이콘을 클릭하는 GUI(Graphic User Interface) 방식입니다. 그래픽 화면을 띄우는 데는 컴퓨터 자원 소모가 크기 때문에 서버 용도로는 부적합합니다.

리눅스도 처음 설치하면 GUI 모드로 설치되지만, 서버로 활용할 때는 내가 조금 불편하더라도 게스트(클라이언트)에게 서비스를 제공하는 것이 우선이기 때문에 CLI 모드로 전환해서 사용합니다.

리눅스의 장점

  1. 안정성 — 서버의 가장 중요한 역량은 무정지입니다. 서버가 꺼지면 아주 큰 문제가 되는데, 리눅스는 재부팅 없이도 수리·업데이트가 가능해 운영 중에도 유지보수를 할 수 있습니다.
  2. 모듈화(가벼움)와 유연성 — 레고 블록처럼 원하는 부품만 조합할 수 있습니다. 그래픽 요소를 전부 빼고 계산과 통신에만 집중하면 가벼워지므로, 손바닥만한 라즈베리파이나 스마트폰, 냉장고 등 사이즈에 상관없이 어디서나 사용할 수 있습니다.
  3. 현대 기술의 표준 — 클라우드, 인공지능, 도커 등 IT 업계의 핵심 기술이 리눅스를 기준으로 개발됩니다. AWS나 구글 클라우드에 서버를 만들면 대부분 리눅스가 기본 설치되어 있습니다.
  4. 무료

핵심 구조 — 커널과 쉘

리눅스 계층 구조

  • 쉘(Shell): 명령어 해석기입니다(GUI로 치면 파일 탐색기에 해당). 로그인을 해야 할당받을 수 있습니다.
  • 커널(Kernel): 운영체제의 심장으로, 외부의 접근을 아주 제한된 방식으로만 허가합니다. 원칙적으로 쉘로부터 시스템 콜을 통해서만 통신하지만, 성능을 위해 다른 방식을 허용하기도 합니다.

명령어 실행 과정

사용자(명령어 작성) → 쉘(명령어 파싱 및 해석) → (시스템 콜) → 커널(파일 시스템 API 처리 후 반환) → (하드웨어 제어) → 하드웨어(디스크 읽기) → 쉘(결과를 역방향으로 반환, 화면 출력)

커널의 핵심 역할

  1. 프로세스 관리: 멀티태스킹(여러 프로그램을 동시에 실행할 수 있도록 CPU 시간을 나누고 할당)
  2. 메모리 관리: 각 프로그램에 RAM 영역을 할당·회수, 메모리 침범 방지
  3. 파일 시스템 관리: 디스크에 파일을 읽고 쓰는 작업 처리, 다양한 파일 시스템 형식 지원
  4. 장치 드라이버 관리: 네트워크 카드, 그래픽 카드 등 물리적 장치와 통신하는 드라이버 로드 및 관리

디렉터리 구조

우분투 기준 최상위 트리 구조는 다음과 같습니다.

  • bin: 기본 실행 명령어
  • boot: 부팅에 필요한 핵심 커널 파일
  • dev: 물리적 장치 파일
  • etc: 환경 설정 파일
  • home: 사용자가 실질적으로 작업하는 공간 — 백업할 때는 보통 home 디렉터리를 백업합니다.
  • mnt: 관리자가 추가 하드디스크를 수동으로 마운트할 때 쓰는 디렉터리
  • opt: 패키지를 설치할 때 기본값으로 설치되는 디렉터리
  • root(계정): 실제 디렉터리라기보다 관리자를 뜻합니다. 해킹 시 목표가 되는 관리자 계정이며, sudo를 사용한 명령어는 바로 이 root 계정으로 실행됩니다.
  • tmp: 임시 파일 저장
  • usr: 윈도우의 "Program Files"와 같은 역할로, 각종 프로그램이 설치됩니다.
  • var: 로그 파일 등 용량이 계속 변하는 데이터를 보관

리눅스는 윈도우처럼 디스크를 여러 파티션으로 나눠 드라이브 문자를 붙이는 대신, USB나 CD 같은 매체도 전부 하나의 디렉터리 트리 아래로 마운트해서 관리합니다.

루트 디렉터리 관찰 포인트

  • /proc 디렉터리: 숫자로 된 하위 디렉터리들이 많이 보이는데, 이 숫자들은 프로세스 번호(PID)를 의미합니다. 이렇게 특수한 상황에서 사용되는 자원들이 이곳에 저장됩니다.
  • swap.img: 시스템이 돌아가는 데 필수적인 메모리 확장 용량을 확보해 두는 파일입니다.

런레벨 변경(GUI → CLI)

sudo systemctl set-default multi-user.target

sudo는 관리자 모드로 실행하는 명령어이고, systemctl은 운영체제를 관리하기 위한 명령어입니다.

패키지 인덱스 동기화 및 시스템 업데이트

# 패키지 목록 업데이트 (많이 사용)
sudo apt-get update

# 패키지 목록에 맞게 업그레이드
sudo apt-get upgrade [-y]

apt-get update는 패키지 목록을 최신화하는 명령으로, 패키지를 새로 받거나 변경 사항이 생겼을 때마다 사용합니다. upgrade 실행 중에는 모든 패키지를 받을지 물어보는데, -y 옵션을 붙이면 확인 없이 진행됩니다.

apt와 apt-get은 같은 동작(패키지를 찾아서 실행)을 수행합니다. 다만 apt-get은 옵션 설정이 더 용이합니다.

리눅스의 동시 처리 특성

리눅스는 여러 개의 터미널로 원격 접속해서 동시에 작업할 수 있습니다. 예를 들어 yes 명령어로 y를 무한대로 계속 보내는 작업을 하면서도 동시에 다른 작업을 할 수 있습니다. 반면 윈도우의 명령 프롬프트는 도스(DOS)에서 발전한 것이라 동시 처리에 적합하지 않습니다.

파일 및 디렉터리 제어

각 명령어의 옵션은 명령어와 따로따로 외우기보다 한 덩어리로 외우는 것이 좋습니다. 옵션이 명령어마다 조금씩 다르지만 비슷한 의미(예: -a는 전체, -t는 시간 관련)를 갖는 경우가 많습니다. 옵션은 ls -altr처럼 여러 개를 한 번에 묶어 쓸 수도 있습니다.

ls

$ ls
$ ls /home/user
$ ls -l
$ ls -altr
$ ls -lh

$ ls -altr ./foo    # 하위 디렉터리인 foo 내부의 파일 조회
  • -l: 상세 형식으로 출력
  • -a: 숨김 파일(.으로 시작)을 포함하여 모두 표시
  • -t: 수정 시간 기준으로 정렬
  • -r: 역순으로 정렬(쉘 출력은 아래로 갈수록 최근 것이 보이는 게 편해서 자주 씀)

ls -altr는 그냥 한 단어처럼 외워두는 것이 좋습니다.

cd

$ cd /home/user      # 절대 경로로 이동
$ cd ./Documents     # 상대 경로로 이동
$ cd ..              # 상위 디렉터리로 이동
$ cd ~               # 홈 디렉터리로 이동
$ cd                 # 홈 디렉터리로 이동
$ cd -               # 이전 디렉터리로 이동
$ cd /               # root로 이동
  • 절대경로: /로 시작하며 root를 기준으로 작성합니다(윈도우의 전체 경로 표시와 비슷).
  • 상대경로: /로 시작하지 않으며 현재 위치를 기준으로 작성합니다.
$ cd /home
$ cd ./../    # ./ 는 생략 가능(현재 위치가 기본값)
$ cd ~/test   # 홈 디렉터리 하위의 test로 이동

pwd

$ pwd

현재 경로를 출력합니다.

touch

touch [파일명] — 파일(디렉터리가 아님)을 만드는 명령어입니다.

mkdir

$ mkdir [디렉터리명] [디렉터리명] ...  # 가변 인자
  • -p: 상위 디렉터리가 없을 경우 자동으로 함께 생성(parent). 예를 들어 ./foo/test처럼 상위 디렉터리(foo)가 없는 경로를 한 번에 만들 때 사용합니다.
  • -m: 생성 시 권한을 지정하는 옵션이지만 실무에서는 거의 사용하지 않습니다. 만들고 나서 필요하면 권한을 바꾸는 방식을 씁니다.

rm

$ rm file.txt          # 파일 삭제
$ rmdir -r myfolder     # 디렉터리 재귀 삭제(예시 표기)
$ rm -f file.txt        # 강제 삭제(확인 없음)
$ rmdir -rf myfolder    # 디렉터리 강제 재귀 삭제(예시 표기)
$ rm -i *.log           # 삭제 전 확인 묻기
  • rm은 파일 삭제, rmdir은 디렉터리 삭제용입니다.
  • -r: 재귀 삭제 / -f: 강제 삭제(force) / -i: 삭제 전 확인
  • 실무에서는 -rf를 기본으로 많이 사용합니다.
  • 하위 디렉터리가 있으면 rmdir만으로는 삭제되지 않습니다. 하위 파일까지 지우려면 -r, 제약 조건이 있는 파일도 그냥 지우려면 -f, 단계별로 확인하며 지우려면 -i를 사용합니다.
주의 — rm -rf /는 절대 사용 금지입니다. 시스템 전체가 삭제됩니다. 항상 경로를 확인하세요.

cp

$ cp /etc/passwd ./mypasswd
$ cp -r /etc ./etc_backup   # 디렉터리(절대 경로) 복사
$ cp -r etc etc_backup      # 디렉터리(상대 경로) 복사

# 아래 명령어는 모두 같은 동작
$ cp -r -f /etc ./etc_backup
$ cp -r --force /etc ./etc_backup
$ cp -rf /etc/passwd ./mypass.txt

파일이나 디렉터리를 복사(copy)하는 명령어입니다.

  • -r: 하위 디렉터리도 재귀적으로 복사
  • -f: 강제로 복사
  • -i: 대상 파일이 이미 존재하면 덮어쓰기 전에 확인
  • -p: 원본의 권한, 타임스탬프, 소유자를 유지
  • -u: 원본이 대상보다 최신일 때만 복사
  • -v: 복사되는 파일명 출력

mv

mv [옮길 파일(디렉터리)] [결과 파일(디렉터리)]

파일이나 디렉터리의 위치를 옮길 때 쓰지만, 이름을 바꿀 때도 사용합니다.

파일명을 바꾸는 방식은 크게 삭제 후 재생성하는 방법과 mv를 쓰는 방법이 있습니다.

자가 학습 도구

man

man [명령어]

매뉴얼 문법에서 대괄호([]) 부분은 생략 가능한 부분입니다. 섹션 번호를 통해 명령어부터 시스템 콜 관련 명령어까지 다양한 내용을 볼 수 있지만, 실무에서는 섹션 1(명령어)만 잘 활용하고 나머지는 검색으로 해결하는 경우가 많습니다.

history

$ history
$ history 10   # 최근에 실행한 10개의 명령어만 출력
$ history -c   # 현재 메모리에 있는 명령어 기록 삭제
$ history -w   # 현재까지의 기록을 파일(~/.bash_history)에 저장
$ history > [파일명]  # 모든 히스토리를 파일로 저장

쉘에 입력했던 명령어들의 과거 기록을 출력합니다. 저장하거나 재실행할 수 있어 작업 효율화에 필수적인 명령어입니다. -w는 원래 로그아웃 시점에 저장되는 기록을 즉시 저장합니다.

히스토리 재실행

  • !!: 가장 마지막에 실행한 명령어를 그대로 재실행
  • ![숫자]: history 목록에서 해당 번호의 명령어를 재실행
  • ![시작 명령어]: 가장 최근에 해당 문자열로 시작하는 명령어를 재실행
  • !?[포함할 문자열]?: 명령어 중간에 해당 문자열이 포함된 최근 명령어를 찾아 재실행
  • ^[변경 전 값]^[변경 후 값]: 직전 명령어에서 특정 문자열을 치환해 재실행(오타 수정용)

$ cat [파일명]              # 파일 내용 출력
$ cat -n [파일명]           # 각 줄의 번호도 함께 출력(코드 리뷰 시 유용)
$ cat [기존 파일] > [새로운 파일]  # 파일 복사
$ cat [파일1] >> [파일2]         # 파일1의 내용을 파일2에 누적

파일 내용을 그대로 출력하거나 여러 개의 텍스트 파일을 하나로 병합(concatenate)합니다. >는 출력 방향을 파일로 틀어서 저장하고, >>는 값을 누적합니다. >는 같은 내용이 중복 저장되지 않는 반면 >>는 같은 값도 중복 누적됩니다.

file

$ file [파일명]

지정된 파일의 종류(타입)을 확인하는 명령어입니다.

tail

$ tail server.log
$ tail -n 15 /etc/passwd
$ sudo tail -f /var/log/syslog

텍스트 파일의 끝부분을 출력합니다. -n은 출력 개수 지정, -f는 실시간 모니터링입니다. 서버 환경에서 실시간으로 생성되는 로그 파일을 모니터링할 때 가장 빈번하게 사용되는 관제 도구입니다. -F 옵션을 쓰면 중간에 파일이 닫히더라도 계속 출력을 이어갈 수 있습니다.

grep

$ grep "찾을 단어" [파일명]
$ sudo grep "Fail" /var/log/*
$ grep -r "sshd" /etc/
$ sudo cat auth.log | grep -i "sudo" | grep -v "solcho"

텍스트 파일 내용이나 다른 명령어의 출력 결과에서 특정 문자열(패턴)이 포함된 줄을 찾아 출력합니다. 실무에서 파이프라인(|)과 함께 아주 자주 사용됩니다.

  • -r: 현재 디렉터리뿐 아니라 모든 하위 디렉터리의 파일까지 확인
  • -i: 대소문자 구분 없이 검색
  • -v: 지정한 패턴이 포함되지 않은 줄만 출력(주로 다른 검색과 중첩해서 사용). 예: ps -ef | grep "nginx" | grep -v "grep"처럼 grep 자기 자신이 검색되는 것을 제외할 때 사용
  • -n: 검색된 줄이 원본 파일의 몇 번째 줄인지 행 번호도 함께 출력
  • -q: 출력 자체를 억제하고 결과만 간결하게 확인
  • -E: 검색 조건이 두 가지 이상일 때 사용
  • 출력값 없애기: > /dev/null(표준 출력만 억제), 2>/dev/null(파일이 없을 때 나는 에러 메시지도 억제)

파이프라인 활용 예시:

ps -ef | grep nginx              # 특정 프로세스 찾기
history | grep ssh               # 과거 실행한 명령어 찾기
cat app.log | grep "error" | grep -v "timeout"   # error 중 timeout 제외하고 출력

관리자 권한(UID 0)으로 접근 중인 계정이 있는지 확인: grep ":0:" /etc/passwd

find

$ find [기준 디렉터리] [검색 조건] [수행할 액션]
$ find /etc -name "pass*"          # etc 디렉터리에서 pass로 시작하는 파일명
$ find ./ -name ssh_config -print  # ssh_config라는 파일의 경로 출력

디렉터리 트리를 재귀적으로 탐색해 이름, 크기, 수정 시간, 접근 권한 등 조건에 맞는 파일이나 디렉터리를 검색하는 명령어입니다. 정확한 파일명을 모를 때 많이 사용하며, 옵션 순서가 중요합니다(틀리면 에러 로그로 알려줍니다).

  • -type [f/d/l]: f(일반 파일), d(디렉터리), l(심볼릭 링크)
  • -size: 파일 크기로 검색
  • -mtime: 수정된 날짜로 검색
  • -perm: 접근 권한을 가진 파일을 검사(백도어 탐지에 활용 — 침입자가 재침투를 위해 관리자 권한을 가진 쉘을 몰래 만들어두는 경우를 찾아냄)

실무 핵심 — -exec로 찾아낸 파일에 즉시 명령을 내릴 수 있습니다(파이프 불필요). 명령이 끝났음을 알리려면 반드시 {} \;로 마무리합니다.

$ find /var/www -type f -perm 777 -exec chmod 644 {} \;

백도어 탐지 예시(SetUID 비트가 설정된 파일 찾기):

find / -type f -perm -4000

권한 표시가 -rwsr-xr-x처럼 실행 위치가 x가 아니라 s로 나오면 일반적인 방식과 다르게 실행되는 파일이므로 주의가 필요합니다.

권한 및 소유권 관리

파일 권한에 대한 이해

파일 정보는 [파일, 폴더 여부(1)] / [Owner 권한(3)] / [Group 권한(3)] / [Other 권한(3)] 형태로 표시됩니다. 예를 들어 -rw-r--r--는 파일이며, 소유자는 읽고 쓰기가 가능하고 그룹과 그 외 사용자는 읽기만 가능하다는 뜻입니다.

각 권한은 비트로 표현됩니다: 읽기=4, 쓰기=2, 실행=1. 권한을 읽을 때는 세 개의 숫자로 표현합니다(보통 644 또는 755를 많이 사용). 예: -rw-r--r-- → 644

실행을 하려면 읽을 줄 알아야 하므로, r과 x는 보통 함께 부여합니다.

chmod

$ chmod [부여할 권한] [권한을 변경할 파일/디렉터리]
$ chmod u+rwx g+rx o+rx test

# 많이 사용
$ chmod 644 [텍스트 파일] (-R)
$ chmod 755 [실행 파일] (-R)
$ chmod 600 [비밀 파일] (-R)
  • -R: 하위 파일까지 권한을 일괄 변경(권한은 중요하기 때문에 대문자 옵션)
  • 755: 디렉터리/실행 파일 표준
  • 644: 일반 텍스트 문서 표준
  • 실행(1)만 단독으로 갖는 경우는 거의 없습니다(읽어야 실행 가능하므로).
  • 쓰기 권한은 수정이 가능하다는 뜻이므로, 되도록 root 계정만 갖도록 하는 것이 안전합니다.
주의 — -R로 일괄 변경할 때 디렉터리 권한이 먼저 바뀌므로, 하위 파일 접근 시 오류가 발생할 수 있습니다.

chown

$ chown [user] [파일명]          # 소유자만 변경
$ chown [user]:[group] [파일명]  # 소유자와 그룹을 동시에 변경
$ chown :[group] [파일명]        # 그룹만 변경

소유자와 그룹을 동시에 변경하는 경우가 가장 많습니다. 하위 디렉터리까지 일괄 변경하려면 -R 옵션을 사용합니다.

chmod와 chown은 거의 항상 관리자 권한(sudo)과 함께 사용해야 합니다. 악의적인 사용자가 함부로 소유권(권한)을 넘기는 것을 방지하기 위함입니다.

stat

$ stat [옵션] [파일명]
  • -c: 사용자 정의 형식으로 정보를 출력
  • -f: 해당 파일이 저장된 파일 시스템의 정보를 출력
  • -t: 디렉터리나 파일 정보를 요약하여 출력
  • 포맷 %a: 8진수로 된 파일 권한

프로세스 관리

ps

$ ps
$ ps -f
$ ps -ef
$ ps -ef | grep nginx

현재 실행 중인 프로세스 목록을 출력하는 명령어로, 어떤 프로그램이 돌아가는지 확인하고 관리할 때 사용합니다.

  • -e: 시스템에서 실행 중인 모든 프로세스를 출력
  • -f: 풀 포맷으로 출력(UID, PID, PPID, 시작 시간 등 상세 정보)

ps -f 결과에는 UID(유저 id), PID(프로세스 id), PPID(부모 프로세스 id)가 표시됩니다. 프로세스는 계층적으로 부모를 가지며, 계속 거슬러 올라가면 결국 init과 커널로부터 각각 PID 1과 2로 생성된 자식 프로세스들이 아주 많습니다.

  • 부모 프로세스가 죽으면 자식 프로세스도 죽습니다. 그래서 init(1)이나 커널(2)에 문제가 생기면 서비스 전체가 망가질 수 있습니다.
  • 고아 프로세스: 부모 프로세스가 죽었는데도 살아있는 자식 프로세스. 이를 악용해 쓸데없는 프로세스를 무한정 생성하면 메모리 할당이 계속되어 정상 프로세스에도 문제가 생기는 DoS 공격이 가능합니다. 이 개념은 컨테이너 기술의 중요한 기본 바탕이 됩니다.

kill

$ ps -ef | grep tomcat
$ kill 4512

$ ps -ef | grep bash | grep solcho
$ kill -9 2190

시그널 번호로 프로세스를 종료합니다.

  • 15(기본값): 안전하게 종료
  • 9: 강제 종료. 실질적으로 가장 많이 쓰는 옵션

killall은 동일한 이름의 자식 프로세스가 수십 개 떠 있을 때 이름으로 일괄 종료하는 명령어이고, pkill은 가장 먼저 찾은 것만 종료합니다.

top

$ top

현재 시스템의 전반적인 상태(CPU, 메모리, 부하율)와 실행 중인 프로세스들의 자원 점유율을 실시간으로 모니터링하는 종합 상황판 명령어입니다. ps가 특정 시점의 스냅샷("사진")이라면 top은 실시간으로 갱신되는 화면입니다.

좀비 프로세스는 고아 프로세스와 비슷한 개념으로, 할 일이 없는데도 메모리만 계속 할당받고 있는 프로세스를 말합니다. htop은 top을 더 시각화해서 보기 편하게 만든 도구입니다.

watch

$ watch -n 1 ps    # 1초마다 ps를 실행한 결과를 보기
$ watch -n 1 ls

명령어를 특정 시간마다 반복 실행하고 그 결과를 모니터링하는 명령어입니다. 실무에서는 top보다 더 자주 사용되기도 합니다.

df

디스크 사용량을 확인하는 명령어입니다. 기본 출력은 1KB 블록 단위라 읽기 힘듭니다.

  • 실무 표준 옵션 -h: 사람이 읽기 편한 단위(MB, GB, TB)로 변환. 사실상 항상 사용합니다.
  • 서버 장애 분석 필수 옵션 -T: 각 파티션의 파일 시스템 형식(예: 리눅스의 ext4, 윈도우의 ntfs)도 함께 출력
  • 서버 장애 분석 필수 옵션 -i: 디스크 용량이 아니라 파일 메타데이터를 저장하는 아이노드의 사용량과 남은 개수 출력

du

$ du -sh /var/log

디렉터리나 파일이 디스크 용량을 얼마나 차지하는지 확인하는 명령어로, 디스크가 가득 찼을 때 용량을 갉아먹는 원인을 색출하는 추적 도구입니다.

  • -s: 하위 내용 전부가 아니라 지정한 대상의 총합계(요약) 용량만 출력
  • -h: 사람이 읽기 편한 단위로 자동 변환
df가 숲이라면 du는 나무입니다 — df로 전체 용량 경고를 확인하고, du로 문제가 되는 원인을 좁혀갑니다.

네트워크 명령어

ip / ifconfig

서버의 네트워크 인터페이스(랜카드) 상태를 확인하고 IP 주소, 서브넷 마스크, MAC 주소 등을 조회·제어하는 기본 명령어입니다. 현재는 ip 명령어가 공식 표준이며, ifconfig는 기본적으로 설치되어 있지 않은 경우가 많습니다.

  • ens33 등: 인터페이스 이름
  • mtu: 한 번에 보낼 수 있는 데이터 크기(Byte)
  • inet: IPv4 주소(10진수 표현, 실제로는 8비트씩 4자리 = 32비트)
  • inet6: IPv6 주소(16진수 표현, 2바이트씩 8자리 = 128비트)
  • ether: MAC 주소. 하드웨어 랜카드에 적힌 이더넷 주소(16진수, 1바이트씩 6자리)

공유기가 MAC 주소와 IP 주소를 매핑해 두고, 데이터가 전송되면 공유기가 MAC 주소에 해당하는 IP로 통신을 처리해 줍니다. 이더넷 주소는 임의로 변경할 수 있는데, 변경된 채로 데이터를 전송하면 스위치 기능이 마비되는 스위치 재밍 공격(스푸핑의 일종)이 발생할 수 있습니다.

$ sudo ip link set ens33 down
$ sudo ip link set ens33 up

$ sudo ifconfig ens33 down

네트워크 장치를 끄는 것은 해킹 방어나 시스템 점검 시 랜카드 연결을 물리적으로 뽑는 것과 같은 효과를 냅니다.

주의 — SSH로 원격 접속 중인 랜카드를 down 시키면 서버와 영영 통신이 끊어질 수 있습니다.

ping

$ ping [(url/ip) 주소]
$ ping www.google.com
$ ping -c 4 8.8.8.8

특정 서버나 네트워크 장비가 통신 가능한 상태인지 확인하는 진단 명령어로, ICMP(Internet Control Message Protocol) 프로토콜을 사용합니다. 윈도우와 달리 리눅스는 기본적으로 요청을 무한대로 보냅니다.

  • -c: 지정한 횟수만큼만 패킷을 보내고 자동 종료
  • -s: 패킷 크기 지정(정상 패킷은 64바이트). 규격 최대치인 65,535바이트를 꽉 채운 거대한 패킷을 보내면 네트워크 중간에서 수백 개로 쪼개지고(단편화), 목적지가 이를 다시 조립하다 버퍼 오버플로우를 일으켜 다운되는 Ping of Death 공격이 발생할 수 있습니다. 쪼개진 패킷의 순서표를 고의로 겹치게 조작해 CPU를 과부하시키는 Teardrop 공격도 있습니다(현재는 대부분 방어됨).

netstat

$ sudo netstat -anp | more
$ sudo netstat -tulpn
$ sudo netstat -anptu

# 현재 열려있는 서버(LISTEN)의 개수 출력
$ sudo netstat -anptu | grep -i listen | wc -l

네트워크 연결 상태를 출력하는 명령어입니다.

  • -a: 모든 연결 출력
  • -t: TCP 연결 출력
  • -u: UDP 연결 출력
  • -l: 현재 연결 대기 중(Listening)인 포트만 출력
  • -p: 해당 포트를 사용 중인 PID와 프로그램 이름 출력(보안상 sudo 권한 필요)
  • -n: IP와 포트 번호를 도메인/서비스명으로 변환하지 않고 숫자 그대로 빠르게 출력. 변환을 시도하면 못 찾을 때 응답이 늦어지므로 -an을 항상 같이 씁니다.

결과 예시(sudo netstat -anptu):

tcp 0 0 0.0.0.0:22 0.0.0.0:* LISTEN 1/init
tcp 0 0 192.168.6.128:22 192.168.6.1:55243 ESTABLISHED 1535/sshd: solcho

init(PID 1)에서 22번 포트(SSH)가 열려 있고, solcho라는 사용자가 22번 포트로 TCP 접속해 있다는 뜻입니다. LISTEN은 서버가 열려 대기 중, ESTABLISHED는 연결이 맺어진 상태를 의미합니다. 22번은 SSH, 80번은 웹서버, 53번은 DNS로, 1024번까지의 포트는 누구나 알 만한 Well-known 포트입니다.

netstat -i 결과에서 RX는 받은 내용, TX는 전송 내용, ERR은 에러, DRP는 문제가 있어 버려진 내용을 의미하며, lo는 루프백(자기 자신) 주소입니다.

netstat -rn은 라우팅 테이블을 출력합니다.

  • Destination(목적지): 패킷이 도달하려는 대상 네트워크/호스트 주소
  • Gateway(게이트웨이): 외부 네트워크로 나가기 위해 거쳐야 하는 라우터 주소(0.0.0.0이면 로컬에 직접 연결되어 게이트웨이가 필요 없다는 뜻)
  • Genmask(넷마스크): 목적지 주소 범위를 지정하는 마스크값
  • Flags: U(경로 활성화), G(게이트웨이 사용 경로)
  • Iface: 해당 경로로 패킷을 보낼 때 사용하는 네트워크 카드 이름

traceroute

$ traceroute -n 8.8.8.8   # 윈도우는 tracert -d 8.8.8.8

내 컴퓨터에서 출발한 패킷이 목적지 서버에 도달하기까지 거쳐가는 모든 중간 라우터의 경로와 지연 시간을 추적하는 명령어입니다. -n은 도메인 이름 변환 없이 숫자 IP로 빠르게 출력합니다.

결과에서 별표(*)는 방화벽 같은 보안 정책 때문에 응답이 막힌 것을 의미합니다. DDoS 방어나 네트워크 구조를 숨기기 위해 ICMP 에러 응답을 고의로 무시(drop)하도록 설정하는 경우가 많습니다. 이런 방식으로 라우팅 경로를 추적해 이동 과정을 확인하거나 느려지는 구간을 파악할 수 있습니다.

홉(hop)은 거쳐갈 수 있는 라우터의 개수를 의미합니다.

curl / wget

$ curl http://www.naver.com
$ wget -O blue_cat.webp https://example.com/blue_cat.webp
  • curl: URL에 해당하는 결과를 화면(표준 출력)으로 보여줍니다.
  • wget의 -O: 다운로드한 파일을 지정한 이름으로 저장(안 쓰면 원본 이름 사용)
  • wget의 -c(continue): 중단된 다운로드를 이어서 진행(대용량 파일 작업에 필수)
  • wget의 -b(background): 다운로드를 백그라운드로 돌리고 터미널 제어권을 즉시 반환(진행 상황은 wget-log 파일에 기록)

curl vs wget — 설계 철학과 주 용도가 다릅니다. curl은 결과를 기본적으로 터미널 화면에 출력하며 REST API 테스트나 헤더 분석 등 '통신' 자체에 집중합니다. wget은 결과를 기본적으로 파일로 저장하며 끊긴 다운로드 이어받기나 디렉터리 구조 통째 복사 등 '안정적인 다운로드'에 특화되어 있습니다. 기능이 비슷하므로 하나만 잘 알아두어도 크게 문제 없습니다.

원격 접속 및 파일 전송

ssh

$ ssh solcho@192.168.6.129

이름이 solcho인 사용자로 IP 주소가 192.168.6.129인 원격 서버에 접속하고, exit로 접속을 종료합니다.

SSH 특징 — 공개키 암호화 방식을 사용해 종단 간(End-to-End) 암호화 통신을 수행합니다. 과거에 쓰던 Telnet이나 rlogin은 데이터를 평문(Plain Text)으로 전송해 같은 네트워크의 해커가 패킷을 엿보면 관리자 비밀번호가 그대로 노출되는 문제가 있었습니다. SSH의 기본 포트는 TCP 22번입니다.

scp(Secure Copy)

scp [옵션] [출발지(계정명@IP주소)] [목적지]

$ scp solcho@192.168.6.128:/etc/passwd ./192.168.6.128_passwd.txt

SSH 프로토콜을 기반으로 로컬 컴퓨터와 원격 서버 간, 또는 서버와 서버 간에 파일을 안전하게 복사하는 명령어입니다. 기존에 쓰던 FTP(File Transfer Protocol)는 데이터를 평문으로 전송해 스니핑에 매우 취약했지만, scp는 ssh의 암호화 통로를 그대로 이용하므로 별도 포트 없이(기본 22번) 안전하게 파일을 주고받을 수 있습니다.

  • 무결성 보장: 전송 중 파일이 변조되지 않았음을 보장
  • 인증 공유: SSH 키 기반 인증이 설정되어 있다면 비밀번호 없이도 전송 가능

WinSCP

윈도우 환경에서 그래픽 친화적인 방식으로 편하게 파일을 복사할 수 있는 SCP 클라이언트 도구입니다.

사용자 및 관리자 권한 제어

sudo

일반 사용자가 보안상 제한된 명령을 실행할 때, 잠시 다른 사용자(보통 root)의 권한을 빌려 실행할 수 있게 해주는 명령어입니다.

관리자(root) 계정으로 직접 로그인하면 안 되는 이유:

  • 위험성: 관리자 계정은 모든 권한을 가지므로, 건드리면 안 되는 부분을 잘못 건드리면 시스템 전체가 다운될 수 있습니다.
  • 책임 추적: 여러 관리자가 같은 root 계정을 공유하면 로그에도 같은 계정으로 기록되어 누가 사고를 쳤는지 확인할 수 없습니다. sudo를 사용하면 관리자 권한을 쓰더라도 실제로 명령을 내린 사용자가 로그에 남습니다.
sudo는 책임 추적을 가능하게 하지만, 그래도 꼭 필요한 경우에만 사용해야 합니다. sudo 실행 시 입력하는 비밀번호는 현재 로그인한 본인의 비밀번호입니다.

su

$ su root     # 비권장
$ su - root   # 표준

Substituted User(또는 Switch User)의 약자입니다. 하이픈(-)을 사용하지 않으면 환경 변수(PATH, 홈 디렉터리 등)가 이전 사용자의 것을 그대로 사용해 꼬일 수 있습니다.

구분sudo(권장)su(주의)
비밀번호자신의 비밀번호상대방(root)의 비밀번호
지속성한 줄만 실행 후 복귀exit로 종료해야 끝남
보안성권한 위임 및 로그 추적 가능root 비밀번호 노출 위험 및 추적 어려움

sudo su

$ sudo su
# 비밀번호 입력 후 관리자 쉘

관리자 권한 사용을 자신의 계정으로 시도(sudo)하는 명령어로, su와 같은 역할이지만 sudo 방식이라 책임 추적이 가능합니다. 모든 사용자가 사용할 수 있는 것은 아니며, 자신의 비밀번호로 root 권한을 쓸 수 있는 특정 사용자 그룹에 속해 있어야 합니다(서버를 생성한 계정은 보통 이 그룹에 포함됩니다).

useradd / usermod / userdel (비추천)

$ useradd test2
$ mkdir /home/test2
$ chown -R test2:test2 /home/test2
$ passwd test2

useradd는 순수하게 계정만 만듭니다. 홈 디렉터리를 만들면 소유자가 root로 생성되므로 chown으로 전환해야 하고, 비밀번호도 passwd로 따로 설정해야 합니다. adduser가 있는 상황에서는 평소 사용할 이유가 거의 없고, adduser를 쓸 수 없는 환경에서만 사용합니다.

adduser / deluser (추천)

$ adduser test1
$ deluser --remove-home test1
$ su - test1    # 유저 권한 사용

유저를 추가하면 비밀번호 지정과 홈 디렉터리 생성이 자동으로 이루어집니다. deluser는 기본적으로 계정만 삭제하므로, 홈 디렉터리까지 지우려면 --remove-home 옵션을 사용합니다.

명령어는 대체로 동사+명사(목적어) 순서로 구성된다고 생각하면 외우기 편합니다.

passwd

$ passwd
$ sudo passwd tester

사용자 계정의 비밀번호를 설정하거나 변경하는 명령어입니다. 관리자는 특정 사용자의 비밀번호를 강제로 바꿀 수 있습니다.

  • -l: 계정을 잠금 처리하여 로그인 차단
  • -u: 잠긴 계정의 잠금 해제
  • -e: 비밀번호 즉시 만료
  • -x: 비밀번호의 최대 유효 기간 설정

압축 및 아카이빙

tar — 묶기

$ tar -cvzf [생성할 파일명.tar.gz(.tgz)] [저장할 파일]   # 백업하기
$ tar -xvzf [해제할 파일명.tar.gz(.tgz)]                # 복원하기

여러 개의 파일과 디렉터리를 하나로 묶거나, 묶인 파일을 다시 풀어주는 명령어로, 소스코드를 배포할 때 가장 널리 사용되는 리눅스의 압축/패키징 표준 도구입니다. 핵심은 "묶는다"는 것이지 압축이 아니라는 점입니다.

  • .tar → 묶기만 함(용량이 줄어들지 않음)
  • .tar.gz(.tgz) → tar로 묶은 뒤 gzip으로 용량까지 압축한 파일(현대 리눅스의 사실상 표준)
  • -c / -x(Create/eXtract): 새 아카이브를 생성할지, 기존 아카이브를 추출할지 결정
  • -v(Verbose): 압축/해제되는 파일 이름을 상세히 출력해 진행 상황 확인
  • -z(gZip): gzip 알고리즘으로 압축 혹은 해제까지 함께 처리
  • -f(File): 처리할 아카이브 파일명을 지정(옵션의 가장 마지막에 오고 바로 뒤에 파일명이 와야 함)

타르 밤(tar bomb): 인터넷에서 다운로드한 파일을 풀었더니 수만 개의 파일이 폴더 없이 쏟아져 나와 작업 공간을 엉망으로 만드는 현상입니다.

tar -tvzf unknown.tar.gz                    # 압축을 풀지 않고 내부 파일 목록만 확인(x 대신 t)
tar -xvzf unknown.tar.gz -C /tmp/safe_zone  # 지정한 디렉터리에서만 압축 해제(격리된 공간이라 안전)

gzip — 압축하기

GNU zip의 약자입니다(명령어 앞에 g가 붙으면 대체로 GNU 라이선스로 만들어진 명령어). 파일 용량을 압축해 디스크 공간을 절약하거나 네트워크 전송 속도를 높이는 대표적인 압축 명령어입니다.

윈도우와 달리 압축을 하면 원본 파일이 사라집니다. 압축 파일을 새로 만든다기보다 파일의 상태 자체를 변경한다고 이해하는 것이 정확합니다.
  • -k: 압축 후에도 원본 파일 유지(Keep)
  • -d: 압축 해제(Decompress)
  • -9: 압축률 지정(숫자가 커질수록 속도는 느려지고 압축률은 높아짐)
항상 압축 파일을 해제하기 전에 내부 파일 목록을 먼저 확인하는 습관을 들이는 것이 좋습니다. 시스템 엔지니어는 항상 서버의 자원과 보안 위협을 함께 고려해야 합니다.

서비스 및 시스템 데몬 관리

systemctl

$ systemctl status ssh
$ systemctl start/stop nginx    # 서비스 시작/종료
$ systemctl restart nginx       # 서비스 재시작
$ systemctl enable/disable nginx

리눅스의 핵심 관리자인 systemd(시스템 데몬)를 제어하는 명령어입니다. 웹서버(Nginx), 데이터베이스(MySQL) 등 백그라운드에서 돌아가는 서비스의 실행, 중지, 부팅 시 자동 실행 여부를 관리하는 서버의 메인 리모컨 역할을 합니다. 시스템 핵심 프로세스를 다루는 작업이므로 sudo 권한이 필요합니다.

  • status: 서비스의 현재 가동 상태, PID, 최근 로그 일부를 출력
  • start / stop: 서비스 시작/종료
  • restart: 다시 시작
  • enable / disable: 부팅 시 자동 실행 여부 설정

패키지 설치 후 서비스 확인 흐름 (nginx 예시)

패키지를 설치하면 /etc/apt/sources.list.d/ 아래에서 배포판 저장소(예: noble, noble-updates) 정보를 확인할 수 있습니다.

$ ps -ef | grep nginx                       # 프로세스 확인
$ netstat -antup | grep -i listen           # 네트워크 연결 확인
$ curl 192.168.6.128                        # 웹 서비스 응답 확인
$ systemctl status nginx                    # 서버 상태 확인
$ systemctl stop nginx                      # 서버 중지

journalctl

$ journalctl
$ journalctl -xeu nginx

systemd가 수집한 모든 시스템 로그(커널, 부팅, 서비스 실행 기록)를 조회·필터링하는 통합 로그 관리 명령어로, 서버 장애 분석과 보안 감사를 위한 "블랙박스" 역할을 합니다.

  • -x(eXtra): 에러 메시지 외에 발생 이유와 해결 방안에 대한 추가 설명을 붙여줌
  • -e(End): 최신 기록부터 화면에 출력
  • -u(Unit): 수많은 로그 중 특정 서비스의 로그만 추출하여 출력

실무에서는 syslog(/var/log/syslog)의 로그에서 검색해보는 경우도 많습니다. journalctl의 데이터는 /var/log/journal 내부에 데이터베이스 형식으로 정리되어 있습니다.

텍스트 편집기

cat으로 파일 만들기

cat은 파일 출력뿐 아니라 파일 생성에도 쓸 수 있는 원시적인 방법입니다. vi조차 없는 최소한의 환경에서 사용하던, 이전 표준 편집기의 대안입니다.

vi/vim — 모드 개념

특수기호와 흐름 제어

다중 실행 및 논리 제어(; && || &)

  • ;: 앞선 명령어의 성공 여부와 상관없이 나열된 순서대로 명령어를 차례로 실행(단순 실행)
  • &&: 앞의 명령어가 성공(종료 코드 0)했을 때만 다음 명령어를 실행. 실무에서 가장 많이 사용됩니다. 
    true && ls
./configure && make && make install
  • ||: 앞의 명령어가 실패(종료 코드가 0이 아님)했을 때만 다음 명령어를 실행. 실질적으로 거의 사용하지 않습니다. 
    false || ls
mkdir /data || echo "디렉터리 생성 실패!"
  • &: 명령어를 백그라운드로 실행. 명령어 종료를 기다리지 않고 즉시 다음 프롬프트를 띄웁니다. 
    sleep 100 &

프로세스 및 데이터 흐름 제어(> >> < << |)

표준 입출력의 방향을 바꾸는 리다이렉션과, 프로세스 사이의 데이터를 연결하는 파이프입니다.

  • 출력 재지정: >(Overwrite, 덮어쓰기), >>(Append, 기존 내용 끝에 추가 — 로그 기록용 표준)
  • 입력 재지정: <, <<는 키보드 타이핑 대신 파일 내용이나 텍스트 블록을 명령어의 입력값으로 전달합니다. 
    mysql -u root -p my_db < backup.sql

cat << EOF > welcome.txt
Hello Linux
EOF
    파일 없이 여러 줄의 텍스트를 즉석에서 파일로 만들거나 설정값으로 입력할 때 쉘 스크립트 자동화에 유용합니다.
  • 파이프(|): 앞 명령의 출력을 뒤 명령의 입력으로 직접 연결해, 여러 도구를 조립함으로써 복잡한 데이터를 가공합니다.

보안 실무 — 블랙홀 /dev/null 활용: 에러 메시지를 숨기거나 불필요한 출력을 제거해 서버의 흔적을 관리할 때 사용합니다. 숫자는 0(표준 입력), 1(표준 출력), 2(표준 에러)를 의미합니다.

find / -name "*.conf" 2>/dev/null

권한 없는 디렉터리에 접근할 때 발생하는 수많은 에러 메시지를 블랙홀로 버리는 예시입니다.

백그라운드 및 포그라운드(& jobs fg bg)

하나의 터미널에서 여러 명령어를 동시에 관리하는 기술로, 응답이 오래 걸리는 작업을 뒤로 보내고 다른 작업을 앞에서 처리할 수 있습니다.

  • &: 명령어를 백그라운드로 실행
  • Ctrl + z: 실행 중인 포그라운드 작업을 일시 중지
  • jobs: 현재 터미널의 작업 목록 확인
  • bg %[번호]: 중지된 작업을 백그라운드에서 재개
  • fg %[번호]: 작업을 다시 포그라운드로 소환

보안 및 운영 실무 — nohup: nohup ./server.sh &처럼 사용하면 터미널 접속이 끊겨도 작업이 계속 실행됩니다. 다만 백그라운드 작업을 과도하게 띄워놓고 방치하면 시스템 자원을 갉아먹는 좀비 프로세스가 될 수 있으므로, ps나 top으로 주기적으로 점검하고 kill로 정리해야 합니다.

네트워크 기초 개념

공유기와 IP 주소, NAT

cmd로 확인하는 IP 주소는 공유기에서 나에게 할당한 실제 내부 주소이고, 외부 사이트(예: 네이버)가 확인하는 IP는 공유기의 대표 주소입니다. 같은 공유기를 사용하는 기기들은 공인 IP는 같지만 내부 사설 IP(예: 192.168.100.x)는 다릅니다.

개인이 외부 서비스를 요청하면 공유기가 자신의 대표 주소로 응답을 받아오는 방식이라, 개인이 아는 IP와 상대 서비스가 아는 IP는 당연히 다릅니다. VMware는 네트워크 어댑터로 NAT을 사용해 주소 변환을 하기 때문에, 같은 공유기를 쓰더라도 다른 컴퓨터의 가상머신(리눅스)에 곧바로 접근할 수는 없습니다.

네트워크 어댑터: 컴퓨터를 유선(이더넷) 또는 무선(Wi-Fi) 네트워크에 연결해 인터넷 신호를 주고받는 필수 하드웨어입니다.
NAT(Network Address Translation, 네트워크 주소 변환): 가상 머신(VM)이 호스트 PC의 IP 주소를 공유해서 외부 인터넷에 접속하게 하는 방식입니다.

VMware 네트워크 어댑터 종류

  • Bridge: 실제 공유기에 직접 연결
  • NAT: 호스트 컴퓨터를 공유기처럼 사용(VMNet 8번 사용)
  • Host-only: 외부와 통신하지 않고 내부망만 따로 구축할 때 사용(VMNet 1번 사용)

동적 네트워크 할당(DHCP)

DHCP는 공유기에 내장되어 있으며, 접속한 기기에 IP 주소를 자동으로 할당합니다. 네트워크 어댑터를 Bridged로 바꾸면 공유기에 직접 연결되므로 DHCP로부터 주소를 할당받습니다.

포트 번호

포트 번호는 16비트로 표현되어 0~65,535까지 존재하지만, 그렇다고 아무 포트나 임의로 열 수 있는 것은 아닙니다.

  • Well-Known Ports(잘 알려진 포트, 0~1023): 주요 네트워크 서비스에 공식적으로 할당된 포트입니다. /etc/protocols에서 프로토콜을, /etc/services에서 well-known 포트를 확인할 수 있습니다.
    • 80: HTTP
    • 443: HTTPS
    • 20, 21: FTP
    • 22: SSH, SFTP
    • 23: Telnet
    • 25: SMTP
    • 53: DNS
    • 69: TFTP
  • Registered Ports(등록된 포트, 1024~49151): 특정 애플리케이션이 등록해서 사용하는 포트로, 임의로 지정해서 열 수 있습니다.
    • 3306: MySQL, MariaDB
    • 3389: RDP
  • Dynamic & Ephemeral Ports(동적/임시 포트, 49152~65535): 클라이언트가 통신할 때 임시로 할당받아 사용하는 포트입니다.

쉘(Shell)과 커널 — 요약

흐름은 사용자 ↔ 쉘 ↔ 커널 ↔ 하드웨어입니다. 쉘은 사용자의 입력을 기반으로 프로그램을 실행해 운영체제의 서비스를 사용할 수 있게 해주고, 커널은 쉘로부터 전달받은 명령을 기계가 이해할 수 있는 형태로 변환해 CPU, I/O, 메모리 등 리소스에 접근하게 해줍니다.

cat /etc/shells
  • sh(Bourne Shell): 최초의 유닉스 쉘로 스크립트를 지원합니다.
  • bash(Bourne Again Shell): 본쉘의 확장판으로 Linux, Mac의 기본 쉘입니다. mv, cp, rm, touch, ls, mkdir, cd, rmdir 등의 명령어가 여기서 추가되었습니다.
쉘은 OS의 외부 계층이고, 커널은 OS의 내부 계층입니다.

리눅스 주요 파일 — /etc/passwd와 /etc/shadow

/etc/passwd: 시스템에 등록된 사용자의 계정과 인증 정보를 관리하는 파일입니다.

사용자계정명:비밀번호 필드(암호화):UID:GID:사용자이름:홈디렉토리:로그인쉘

UID 0은 root 계정을 의미합니다. 일반 사용자로 로그인하면 홈 디렉터리(예: /home/solcho) 위치에서 지정된 로그인 쉘(예: /bin/bash)로 세션이 시작됩니다.

/etc/shadow: 암호화된 패스워드와 패스워드 정책이 기재된 파일입니다. 과거에는 패스워드를 /etc/passwd에 직접 저장했지만, 현재는 /etc/shadow에 암호화된 값을 따로 저장합니다.

사용자 계정명:암호화된 패스워드:마지막 변경:패스워드 최소 사용기간:패스워드 최대 사용기간:경고:비활성화:만료일

암호화된 패스워드 필드는 $로 구분되며 형식은 $algorithm_id$salt$encrypted_password입니다.

  • algorithm_id: 암호학적 해시 알고리즘의 id
  • salt: 각 해시에 첨가하는 랜덤 값(값에 따라 해시 결과가 달라짐)
  • encrypted_password: 알고리즘과 salt로 암호화된 패스워드 값

DNS(Domain Name Service)

www.naver.com 같은 도메인은 원래 끝에 마침표(.)가 붙지만(항상 붙기 때문에 관례적으로 생략합니다), 계층적으로 다음과 같이 해석됩니다.

  • Root DNS: com. 등 최상위 부분(org, kr 등)만 알고 있음
  • com DNS: naver. 부분을 알고 있음
  • naver.com DNS: www.naver.com 전체를 알고 있음

DNS는 UDP를 사용합니다. netstat -antp | more로 확인했을 때 127로 시작하는 주소는 내 컴퓨터 자신의 주소이며, 53번 포트가 DNS 서버로 열려 있는 경우 이는 통신을 위한 외부 노출 주소가 아니라 내 시스템 내부 주소이므로 다른 곳에서 접속할 수 없습니다.
