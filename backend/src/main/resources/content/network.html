네트워크 기초와 패킷 분석

네트워크는 여러 컴퓨터가 정해진 규칙(프로토콜)에 따라 데이터를 주고받는 구조입니다. 이 단원에서는 가정용 네트워크 환경(공유기, IP, DHCP)부터 포트, 리눅스 시스템의 계정/쉘 구조, DNS, 보안 요소, 네트워크 장비, 그리고 OSI 7계층/TCP-IP 4계층의 각 계층별 프로토콜과 패킷 구조, 서브넷 마스크 계산까지 실습에서 다룬 내용을 순서대로 정리합니다.

해시 알고리즘

해시(Hash): 임의의 크기를 가진 데이터(Key)를 고정된 크기의 고유한 값(해시 값, Hash Value)으로 변환하는 알고리즘입니다.

  • 해시는 일반적으로 무언가를 잘게 쪼갠 후 결과물을 생성하는 과정을 뜻한다(해시 브라운도 감자를 잘게 쪼개고 뭉쳤다는 데서 유래).
  • 입력 데이터로부터 유도되기 때문에 동일한 입력은 항상 동일한 해시값을 갖는다.
  • 단방향 암호화 방식 — 해시값에서 원래 데이터로의 역변환은 거의 불가능하다.
  • 해시 충돌: 서로 다른 입력에 대해 동일한 해시값을 출력하는 경우. 충돌이 많을수록 성능이 떨어지므로 최소화해야 하고, 특정 해시값에 값이 몰리는 것도 방지해야 한다.

공유기와 IP 주소

  • cmd로 확인하는 IP 주소는 공유기 내부에서 사용하는 나(단말)의 실제 주소이고, 네이버 같은 외부 사이트가 확인하는 IP 주소는 공유기의 주소다.
  • 같은 공유기를 쓰는 기기들은 192.168.100.x처럼 앞부분 대역이 같다(리눅스에서도 192.168 대역이 보이면 공유기를 통해 접속 중이라는 뜻).
  • 네트워크 과정: 개인이 네이버 서비스를 요청하면, 공유기가 자신의 주소로 네이버의 응답을 대신 받아온다. 그래서 개인이 알고 있는 IP 주소와 네이버가 알고 있는 주소는 서로 다르다.
  • VMware는 네트워크 어댑터로 NAT을 사용하여 주소 변환을 하기 때문에, 같은 공유기를 쓰더라도 다른 컴퓨터의 가상머신(리눅스)에 곧바로 접근할 수는 없다.

네트워크 어댑터: 컴퓨터를 유선(이더넷) 또는 무선(Wi-Fi) 네트워크에 연결해 인터넷 신호를 주고받는 필수 하드웨어.
NAT(Network Address Translation, 네트워크 주소 변환): 가상 머신(VM)이 호스트 PC의 IP 주소를 공유하여 외부 인터넷에 접속하게 하는 방식.

VMware 네트워크 어댑터 종류

  • Bridge: 실제 공유기에 직접 연결한다.
  • NAT: host 컴퓨터를 공유기처럼 사용한다(VMNet 8번 사용).
  • Host-only: 외부와 통신하지 않고 내부망을 따로 구축할 때 사용한다(VMNet 1번 사용).

게이트웨이

게이트웨이: 다른 네트워크로 나가기 위한 통로(보통 공유기나 라우터의 주소).

cmd에서 확인: ipconfig /all

  • DHCP(동적 주소 할당)를 사용한다.
  • 게이트웨이 주소가 192.168.100.1이고 서브넷 마스크가 255.255.255.0이라면 다음과 같이 해석한다.
  • 네트워크 주소: 192.168.100.0
  • 게이트웨이 주소: 192.168.100.1(또는 .254)
  • 브로드캐스트 주소: 192.168.100.255

리눅스에서 Gateway 확인

netstat -rn

VMware에서 확인

Edit > Virtual Network Editor 메뉴에서 네트워크 구성을 확인할 수 있고, DHCP Settings에서 변경도 가능하다(환경에 따라 안 될 수도 있다).

동적 네트워크 할당(DHCP)

  • DHCP가 IP 주소를 할당하며, DHCP 서버는 공유기 안에 있다.
  • 네트워크 어댑터를 Bridged로 변경하면 공유기에 직접 연결되기 때문에 DHCP로부터 주소를 할당받는다.

포트 번호(Port)

  • 포트번호는 16비트로 표현되어 0~65,535까지 존재한다. 그렇다고 임의로 65,535번 전부를 열 수 있는 것은 아니다(아래 구간별 규칙 참고).
  • Well-Known Ports(잘 알려진 포트): 0~1023번. 주요 네트워크 서비스에 할당된 공식 포트다.
    • vi /etc/protocols — 프로토콜 번호 확인 가능
    • vi /etc/services — well-known 포트 확인 가능
    • 80: http / 443: https / 20, 21: ftp / 22: ssh, sftp / 23: telnet / 25: smtp / 53: DNS / 69: tftp
  • Registered Ports(등록된 포트): 1024~49151번. 특정 애플리케이션이나 프로그램이 등록하여 사용하며, 임의로 지정해 열 수 있는 포트다.
    • 3306: mysql, mariadb / 3389: RDP
  • Dynamic & Ephemeral Ports(동적 및 임시 포트): 49152~65535번. 클라이언트가 통신할 때 임시로 할당받아 사용하는 포트다.

쉘(Shell)과 커널

  • 사용자 ↔ 쉘 ↔ 커널 ↔ 하드웨어의 순서로 명령이 전달된다.
  • 쉘(Shell): 사용자가 운영체제의 서비스를 사용할 수 있도록, 사용자의 입력을 기반으로 프로그램을 실행해 주는 역할.
    • 쉘 목록 확인: cat /etc/shells
    • sh(Bourne Shell): 최초의 유닉스 쉘로 스크립트를 지원한다.
    • bash(Bourne Again Shell): 본쉘의 확장판으로 Linux, Mac의 기본 쉘이다. mv, cp, rm, touch, ls, mkdir, cd, rmdir 등의 명령어가 추가되었다.
  • 커널(Kernel): 쉘로부터 전달받은 명령을 기계가 이해할 수 있는 언어로 변환하여 CPU, I/O, 메모리 등 다양한 리소스에 접근해 주는 역할.

쉘은 OS의 외부 계층이고, 커널은 OS의 내부 계층이다.

리눅스 주요 파일: /etc/passwd와 /etc/shadow

/etc/passwd: 시스템에 등록된 사용자의 정보가 담겨 있는 파일로, 사용자의 계정과 인증을 관리한다.

  • 필드 구성: 사용자계정명:비밀번호 필드(암호화):UID:GID:사용자이름:홈디렉토리:로그인쉘
  • UID 0번은 root 계정이다.
  • 로그인을 하면 예를 들어 /home/solcho 위치에서 /bin/bash로 실행된다.

/etc/shadow: 암호화된 패스워드와 패스워드 설정 정책이 기재된 파일. 과거에는 사용자의 패스워드를 /etc/passwd에 저장했지만, 현재는 /etc/shadow에 따로 암호화하여 저장한다.

  • 필드 구성: 사용자 계정명:암호화된 패스워드:마지막 변경:패스워드 최소 사용기간:패스워드 최대 사용기간:경고:비활성화:만료일
  • 암호화된 패스워드는 $로 필드가 구분된다: $algorithm_id$salt$encrypted_password
    • algorithm_id: 암호학적 해시의 id
    • salt: 각 해시에 첨가할 랜덤값. 이 값에 따라 해시값이 바뀐다.
    • encrypted_password: 알고리즘과 salt로 암호화된 패스워드 값

DNS(Domain Name Service)

  • www.naver.com.처럼 원래 마지막에 .이 붙는다(항상 붙기 때문에 보통 생략한다).
    • Root DNS: com. 등 최상위 부분만 알고 있음
    • com DNS: naver.
    • naver.com DNS: www.naver.com
  • DNS는 UDP를 사용한다.
  • netstat -antp | more로 확인 가능
    • 127로 시작하는 주소는 자기 자신(내 시스템)의 주소다.
    • 53번 포트는 DNS 서버 포트이며, 통신을 위한 주소가 아니라 내 시스템 주소로 열려 있는 것이라 외부에서 접속할 수 없다.
    • 상태가 ESTABLISHED이면 연결이 맺어져 있는 상태다.

응답 코드

// 톰캣 서버 로그
192.168.6.1 - - [04/Jun/2026:10:14:46 +0900] "GET /test.html HTTP/1.0" 304 -
192.168.6.1 - - [04/Jun/2026:10:15:10 +0900] "GET /test.html HTTP/1.0" 304 -
192.168.6.1 - - [04/Jun/2026:10:15:10 +0900] "GET /favicon.ico HTTP/1.0" 404 828

성공 응답 코드로 흔히 아는 200이 아니라 304가 뜨는 경우가 있다(개발자 도구에서도 동일하게 확인된다).

  • 304 Not Modified: 요청된 리소스를 재전송할 필요가 없다는 의미.
  • 이전에 요청해서 응답으로 받은 리소스를 재요청했을 때, 달라진 내용이 없어 재전송받을 필요 없이 캐시되어 있는 리소스로 리다이렉션하겠다는 뜻이다.
  • 브라우저 최초 요청 시에는 200이 뜨지만 그 이후 한동안은 304가 뜬다. 서버를 재시작하면 캐시 데이터가 사라지기 때문에 다시 200이 뜬다.

망분리

  • DMZ: WEB 서버가 위치하며, 외부에서 어느 정도 접근이 가능한 공간이다. 모든 방에 접근할 수 있는 서버가 DMZ에 존재하기 때문에, 한번 뚫리면 전체 서버가 뚫리는 것과 같아 아주 철저하게 관리해야 한다.
  • 내부망: WAS 서버가 위치한다.
  • DB도 또 다른 네트워크 망에 존재한다.

같은 네트워크망에 서버들을 함께 두면 공격을 받았을 때 전체 시스템이 다운될 수 있다. 이를 방지하기 위해 서버를 전부 다른 망으로 분리해 둔다.

허니팟(Honeypot)

사이버 보안 분야에서 해커를 유인해 공격 수법과 정보를 파악하는 가상 함정(꿀단지)이다. 목적과 네트워크 구성에 따라 크게 세 가지 위치에 배치한다.

  • 방화벽 앞(DMZ 구간)
  • 내부 네트워크(LAN 내부)
  • 자체 격리된 가상 네트워크(VLAN)

네트워크 보안의 5대 요소

정보 보안의 3대 요소

  • 기밀성: 인가된 사용자만 정보 자산에 접근할 수 있다. 위협 예: 스니핑(Sniffing), 스누핑(Snooping), 사회공학적 공격(Social Engineering)
  • 무결성: 권한을 가진 사용자가 인가한 방법으로만 정보를 변경할 수 있도록 한다(무결성을 해치는 예: 위조화폐). 네트워크 보안에서는 클라이언트와 서버 간의 데이터가 변조되지 않고 전송되는가가 핵심이며, 위협 예로 세션 하이재킹, SQL 인젝션, XSS 같은 웹 취약점 공격이 있다.
  • 가용성: 필요한 시점에 정보 자산에 대한 접근이 가능하도록 한다. 위협 예: 서비스 거부 공격(DoS)

추가 요소

  • 서버 인증: 클라이언트가 올바른 서버로 접속하는가(예: SSL(HTTPS)을 통한 인증).
  • 클라이언트 인증: 올바른 클라이언트가 접속을 시도하는가(예: 아이디와 패스워드). 위협 예: 스푸핑, 세션 하이재킹, 피싱

네트워크 장비 정리

허브

  • 물리 계층(1계층) 장비이며, 리피터는 약해진 전기 신호를 증폭하는 역할을 한다.
  • 여러 호스트의 전기적 신호를 받아 전달받은 그대로 전송만 하는 네트워크 장비다.
  • 전기선이 하나이기 때문에 한 번에 하나의 신호만 처리할 수 있다.
    • 반이중 모드: 1차선 도로처럼 송수신을 번갈아 가면서 하는 통신 방식이며, 충돌이 발생하기도 한다.
  • 요즘은 네트워크 장비로 거의 사용되지 않는다.

스위치

  • 데이터 링크 계층(2계층) → L2 스위치
  • 허브의 충돌을 완화하기 위한 근본적인 해결책으로, 전달받은 신호를 수신지 호스트가 연결된 포트로만 내보낸다.
  • 허브와 마찬가지로 여러 포트에 호스트를 연결할 수 있지만, MAC 주소를 학습해 특정 MAC 주소를 가진 호스트에만 프레임을 전달할 수 있다.
  • 전이중 모드의 통신을 지원(송수신 양방향)하면서 포트별로 콜리전 도메인이 나뉘고, 허브의 충돌 방지 방안이던 CSMA/CD 프로토콜이 필요 없어지면서 속도와 성능이 크게 향상된다.

라우터(≈ 게이트웨이)

  • 네트워크 계층(3계층) → L3 스위치(따로 있지만 비슷해서 구분하지 않기도 한다)
  • 멀리 떨어져 있는 호스트 간의 통신에서 패킷은 여러 라우터를 거쳐 다양한 경로로 이동한다. 서로 다른 네트워크 사이로 데이터가 가장 빠른 길로 갈 수 있게 안내하며, 라우팅 테이블에 통신에 필요한 정보를 저장한다.
  • 홉(hop): 패킷이 호스트와 라우터 간, 혹은 라우터와 라우터 간에 이동하는 하나의 과정.
  • 가정에서는 보통 공유기가 라우터(홈 라우터) 역할을 하며, NAT 기능·DHCP 서버 기능·방화벽 기능 등 여러 장치의 기능을 함축하고 있다.
  • 라우팅 프로토콜
    • IGP: RIP(거리 벡터 — 적은 개수의 홉을 거치는지로 판단), OSPF(링크 상태 — 실질적인 속도로 판단)
    • EGP: BGP

이더넷 케이블 구조

  • 일반 색상선과 흰색+색상선으로 구성되며, 흰색+색상선은 간섭 방지를 위한 선이다.
  • 사용 용도에 따라 다이렉트 케이블 핀맵과 크로스 케이블 핀맵으로 구분한다.

네트워크 프로토콜

프로토콜의 3요소

  • 구문: 데이터의 구조나 포맷
  • 의미: 전송되는 데이터의 각 부분이 무엇을 뜻하는지 미리 정해둔 규칙. 데이터 자체뿐 아니라 오류 제어, 동기 제어, 흐름 제어를 포함한다.
  • 순서: 어떤 데이터를 보낼 것인지, 얼마나 빠르게 보낼 것인지 정의

프로토콜의 기능

  • 캡슐화(데이터에 제어 정보를 덧붙임)
  • 연결 제어
  • 흐름 제어
  • 오류 제어
  • 동기화
  • 다중화
  • 전송 서비스

네트워크 계층 구조

ISO(국제 표준화 기구)는 여러 업체가 만든 시스템 간에 상호연동이 가능한 표준 네트워크 모델을 제정할 필요성을 인식하고 OSI(Open System Interconnection) 네트워크 모델을 발표했다. OSI 7계층은 이론적으로 기술하고 이해할 때 사용하는 참조 모델이고, 실질적으로 구현된 네트워크 구조는 TCP/IP 4계층이다(전송 계층과 인터넷 계층은 보통 OS에 포함된다).

OSI 모델의 목적이 '이상적 설계'라면, TCP/IP 모델은 '실용적 구현'이다.

OSI 7계층 요약

  • 물리 계층: 실제 장치를 연결하는 데 필요한 전기적·물리적 세부 사항을 정의한다(허브, 리피터).
  • 데이터 링크 계층: 물리 계층으로부터 받은 전기 신호를 데이터 형식으로 바꾸고, 다음 계층으로 넘길 때 LAN 카드 정보를 추가한다(스위치, L2 스위치).
  • 네트워크 계층(IP): 경로 찾기, IP 주소 처리, 데이터 우선순위, 데이터를 어디로 보낼 것인지 결정한다(라우터, L3 스위치).
  • 전송 계층(TCP): 데이터를 어떻게 보낼 것인지 결정하며, 양 끝단의 사용자들이 신뢰성 있는 데이터를 주고받을 수 있게 하여 상위 계층이 전달의 유효성이나 효율성을 고려하지 않아도 되게 한다. TCP는 연결 지향 프로토콜, UDP는 비연결 프로토콜이다(L4 스위치).
  • 세션 계층: 양 끝단의 응용 프로세스가 통신을 관리하는 방법을 제공한다. 전이중(Full-Duplex)·반이중(Half-Duplex)·동시 송수신(Duplex) 방식의 통신과 체크 포인팅, 유휴·종료·재시작 과정을 수행하며, TCP/IP 세션을 만들고 없애는 책임을 진다. (다만 이 통신 방식들은 전기 신호를 보내는 방식이라 실제로는 2계층에 더 가까운 내용이다. ethtool <랜카드 이름> 명령으로 랜카드가 어떤 방식으로 이더넷 통신을 하는지 설정을 확인할 수 있다.)
  • 표현 계층: 암호화, 코드 간의 번역을 담당하며 데이터 형식의 차이로 인해 발생하는 응용 계층의 부담을 덜어준다.
  • 응용 계층: 응용 프로세스와 직접 관계하여 일반적인 응용 서비스를 수행한다.

1계층: 물리 계층

  • 시스템 간의 연결선으로, 흔히 랜(LAN)을 뜻한다.
  • 보통 랜 케이블은 CAT 5의 10/100 BASE-T(IEEE 802.3) 또는 CAT 6의 10/100/1000 BASE-T(IEEE 802.3) 선을 사용하고, 전화선은 CAT 1을 사용한다.

통신망의 종류

  • 버스형
  • 스타형(성형)
  • 메쉬형(망형)
  • 링형
  • 토큰링형 — 토큰 + 링형 구조로 수건돌리기처럼 동작한다. 장점이 많지만 설치 비용이 많이 든다.

커넥터

전화선 연결 커넥터는 RJ(Registered Jack)-11, 랜 케이블의 연결 커넥터는 RJ-45를 사용한다.

리피터

  • 네트워크를 연장하기 위한 장비로, 불분명해진 신호 세기를 다시 증가시키는 역할을 한다.
  • 최근에는 리피터 기능이 모든 네트워크 장비에 공통으로 포함되어 있다.

허브와 스위치의 차이

  • 스위치의 예전 형태를 더미 허브, 최근의 스위치를 스위칭 허브라고도 부른다.
  • 허브와 스위치는 형태나 사용 방법은 같지만, 패킷을 모든 곳에 똑같이 복사해 보내느냐 목적지에만 보내느냐가 다르다.
    • 허브는 들어온 전기신호를 연결된 모든 포트에 전달하므로 한 번에 하나의 신호만 처리 가능하다.
    • 스위치는 포트 번호를 판단해서 해당하는 포트에만 신호를 전달하기 때문에, 다른 포트로 들어온 신호도 동시에 처리할 수 있다.
  • 전기 신호를 그대로 흘려보내는 것을 넘어 신호에 대해 판단을 하는 순간부터는 물리 계층이 아니라 데이터 링크 계층이 된다(그래서 스위치는 2계층 장비다).

2계층: 데이터 링크 계층

  • 랜 카드나 네트워크 장비의 하드웨어 주소(MAC 주소)만으로 통신하는 계층이다.
  • 네트워크 카드의 MAC 주소는 윈도우에서 ipconfig /all, 리눅스에서 ifconfig로 확인할 수 있다. MAC 주소는 공장에서부터 찍혀 나오는 주소라 절대 같을 수 없고 달라질 수도 없다.
ifconfig
  • netmask: 서브넷 마스크(예: CIDR 24)
  • inet: IPv4 주소
  • broadcast: 브로드캐스트 주소
  • ether: 이더넷 주소 = 기기의 MAC 주소(물리적 주소, 8 × 6 = 48bit)
  • txqueuelen: 송신 큐 길이(Transmit Queue Length)
  • RX: 수신(Receive), TX: 송신(Transmit) — errors 값을 통해 송수신 과정에서 생긴 문제가 어디서 발생했는지 확인할 수 있다.

MAC 주소

  • 총 12개의 16진수로 구성된다.
  • 앞쪽 6개는 네트워크 카드를 만든 회사(OUI)를 뜻하고, 뒤쪽 6개는 호스트 식별자(Host Identifier)로 각 회사가 임의로 붙이는 일종의 시리얼 번호다.
  • 같은 MAC 주소는 존재하지 않는다(1612가지 조합).

데이터 링크 계층의 프로토콜

이더넷

  • 제록스의 PARC에서 1970년대에 개발한 데이터 링크 계층의 프로토콜이다.
  • 이더넷 패킷(프레임)의 최소 길이는 64Bytes, 최대 길이는 1,518Bytes다.
  • 프레임 구조: Preamble(동기화 요청) → SFD(Start Frame Delimiter, 데이터 시작) → Destination MAC Address(목적지 주소) → Source MAC Address(출발지 주소) → Length or Type(데이터 길이와 타입) → Data → Pad(길이를 맞추기 위한 추가 값) → FCS(Frame Check Sequence, 순서 정보)
  • 이더넷은 1980년대에 발표된 IEEE 802.3 규약의 기초가 되었다. 프로토콜을 지키지 않으면 값을 해석할 수 없어 받아들이지 않기 때문에 프로토콜이 필요하다.

프레임 릴레이(Frame Relay)

  • 불필요한 전송 오류 제어나 흐름 제어 등 복잡한 기능을 최소화하고, 망 종단 장치에서 처리하도록 하여 고속 전송을 실현하는 기술이다.
  • X.25 패킷 교환망보다 최대 10배까지 고속 데이터 전송이 가능하다.

ATM(Asynchronous Transfer Mode)

  • 고속의 데이터를 53Byte 셀로 처리하는 VLSI 기술이다.
  • 실시간 영상 전송과 같은 고속 통신에 사용된다.

데이터 링크 계층의 장비

브리지: 랜과 랜을 연결하는 초기의 네트워크 장치로, 데이터 링크 계층에서 통신 선로를 따라 한 네트워크에서 다음 네트워크로 데이터 프레임을 복사하는 역할을 한다.

스위치: 데이터 링크 계층에서 동작한다. L2 스위치는 연결된 시스템이 늘어날수록 패킷 충돌 때문에 속도가 매우 낮아지는 더미 허브의 문제점을 해결한 방안이다. 콘솔 포트를 통해 장비에 직접 연결해 제어할 수 있다(컴퓨터처럼).

스위칭의 원리

  • 패킷 전송 방식에 따른 구분: 컷스루 방식, 저장 후 전송 방식, 인텔리전트 스위칭 방식
  • 제공하는 경로의 대역폭에 따른 구분: 반이중 방식, 전이중 방식

컷스루(Cut-Through) 방식: 수신한 프레임의 목적지 주소를 확인하고 목적지 주소의 포트로 즉시 전송하여 지연 시간을 최소화한다. 오류가 발생한 패킷은 목적지 장치에서 폐기한다.

(프레임은 데이터 링크 계층의 전송 단위다. 이더넷 패킷을 하나의 프레임으로 보면 된다.)

저장 후 전송 방식(Store & Forward): 전체 프레임을 수신하여 버퍼에 보관했다가 CRC 등의 오류를 확인한 뒤 정상 프레임만 목적지 포트로 전송한다. 패킷 길이에 비례해 전송 지연이 발생하지만 브리지나 라우터보다는 신속하며, 속도가 서로 다른 포트를 연결할 경우 반드시 사용해야 한다. 최근에는 컷스루 방식과 저장 후 전송 방식을 동시에 지원하는 것이 일반적이다.

인텔리전트 스위칭(Intelligent Switching) 방식: 보통 컷스루 모드로 작동하다가 오류가 발생하면 저장 후 전송 모드로 자동 전환해 오류 프레임 전송을 중지하고, 오류율이 0이 되면 다시 컷스루 방식으로 전환한다.

반이중(Half-Duplex) 방식: 양방향 통신 기능을 제공하지만 한 번에 하나의 동작(수신 또는 송신)만 가능하다.

전이중(Full-Duplex) 방식: 송신 포트와 수신 포트를 분리해 반이중 방식보다 성능이 두 배로 뛰어나며, 충돌이 없어 전송 거리 제한을 연장할 수 있다. 기술적으로는 스위치에서만 전이중 방식을 지원할 수 있다.

스위치 테이블

  • 시스템 간의 원활한 통신을 위해 주소 테이블을 생성하고 관리하는 역할을 한다.
  • arp -a 명령으로 확인할 수 있다.
    • 스위치 테이블에 존재하는 주소면 물리적 주소를 바로 찾아서 통신한다.
    • 테이블에 없다면 목적지를 게이트웨이로 하여 보내고, 게이트웨이에서 외부로 통신한다(예: 192.168.100.1이 게이트웨이).

3계층: 네트워크 계층

랜을 벗어난 통신을 하기 위해 네트워크 계층에서 IP 주소를 사용한다.

IP(Internet Protocol)

IPv4 패킷의 헤더 길이는 20byte로 고정이고, 옵션과 데이터는 가변 길이다.

  • Version: IPv4 또는 IPv6(버전에 따라 옵션과 데이터 길이가 달라진다)
  • Internet Header Length(IHL): 헤더 정보
  • Type Of Service(TOS): QoS(서비스 품질)를 구현하기 위해 포함하는 값. QoS는 네트워크에서 중요한 데이터의 우선순위를 정해 안정적인 성능을 보장하거나, 일일 제공 용량 소진 시 속도를 제한하는 기능이다(Precedence, Delay, Throughput, Reliability, Reserved 항목 포함).
  • Total Length(TL): 옵션·데이터를 포함한 전체 길이 정보
  • Identification: 데이터가 너무 커서 패킷이 목적지에서 받아들일 수 없는 경우 게이트웨이가 분할·통합해서 통신하는데, 이때 같은 패킷인지 구분하는 ID 정보
  • Flag: 패킷이 쪼개져 있는지 아닌지 분할 정보를 담은 부분
  • Fragment Offset: 패킷 순서. 예를 들어 Identification 12번 패킷이 Flag mf(More Fragments)로 Fragment Offset 1, 2, 3, 4…로 쪼개져 있다면, 12번 패킷이 쪼개져서 순서대로 보내지고 있다는 뜻이다.
  • Time To Live(TTL): 이 데이터의 수명(얼마나 기다리는지)
  • Protocol: IP 계층의 서비스를 사용하는 상위 계층 프로토콜을 나타낸다(1: ICMP, 2: IGMP, 6: TCP, 17: UDP). 이 값들은 /etc/protocols에 저장되어 있다(포트번호가 아니라 프로토콜 번호이며, 포트번호는 /etc/services에 있다).
  • Header Checksum: 패킷 전달 중 발생할 수 있는 오류 검사를 위한 값. 송신측에서 계산해서 보낸다.
  • Source Address: 송신(출발지) 주소
  • Destination Address: 수신(목적지) 주소

Wireshark로 패킷 확인하기

패킷 캡처 화면은 크게 두 영역으로 나눠 볼 수 있다.

  • 데이터(16진수) 영역: 패킷의 단위가 32비트이기 때문에 16진수도 32비트(4바이트)씩 끊어서 표현된다.
  • 헤더 정보 영역: 각 계층별 헤더 정보(프레임 정보, 이더넷, 인터넷 프로토콜(IPv4), 전송 제어 프로토콜, 전송 계층 보안)를 확인할 수 있다.
    • 이더넷 헤더에서 Destination MAC 주소는 목적지가 내 주소이기 때문에 내 MAC 주소이고, Source MAC 주소는 게이트웨이의 MAC 주소다(외부로부터 들어온 패킷은 게이트웨이를 지나쳐 오기 때문). Type 필드는 다음 프로토콜이 무엇인지(데이터 링크 계층 → 네트워크 계층) 지정한다.
    • IPv4 헤더는 길이가 20 bytes이며, 여기서도 Type 필드가 다음 프로토콜(네트워크 계층 → 전송 계층)을 지정한다.

IP 네트워크 클래스의 구분

시작 주소클래스설명
0A 클래스00000000번부터 01111111(127)번까지의 네트워크. 모두 2⁷(128)개가 가능하고, 하나의 A 클래스 안에 256³(16,777,216)개의 호스트가 존재할 수 있다.
10B 클래스10000000(128)번부터 10111111(191)번까지의 네트워크. 2⁶ × 256(16,384)개가 가능하고, 하나의 B 클래스 안에 256²(65,536)개의 호스트가 존재할 수 있다.
110C 클래스11000000(192)번부터 11011111(223)번까지의 네트워크. 2⁵ × 256²(2,097,152)개가 가능하고, 하나의 C 클래스 안에 256개의 호스트가 존재할 수 있다.
1110D 클래스11100000(224)번부터 11101111(239)번까지의 네트워크. 멀티미디어 방송을 할 때 자동으로 부여된다.
1111E 클래스11110000(240)번부터 11111111(255)번까지의 네트워크. 테스트를 위한 주소 대역이며 사용하지 않는다.

어떤 클래스가 더 좋다고 할 수는 없지만, 하나의 클래스가 가질 수 있는 호스트 개수는 A 클래스가 가장 많다.

  • 유니캐스트: 1:1 통신(A, B, C 클래스)
  • 멀티캐스트: N:M 통신(D 클래스)
  • 브로드캐스트: 1:ALL 통신

IPv6(128비트)

  • IPv4(32비트)의 주소 고갈 문제를 해결하기 위한 대안으로 등장했다.
  • 필수적인 기본 헤더 Base Header와 페이로드 Payload로 구성된다.

ARP(Address Resolution Protocol)

  • 데이터를 전달하려는 IP 주소와 통신에 필요한 물리적인 주소(MAC)를 알아내는 프로토콜이다.
  • 선택된 매체에 브로드캐스트를 통해 특정 IP 주소를 사용하는 호스트가 응답하도록 요구하는 방식을 사용한다.
  • 부팅할 때 올라오며, 새로운 페이지에 접속할 때마다 ARP 프로토콜이 사용되는 것을 확인할 수 있다.

ICMP(Internet Control Message Protocol)

호스트 서버와 인터넷 게이트웨이 사이에서 메시지를 제어하고 오류를 알려주는 프로토콜이다. 대표적인 툴은 ping이다.

Type1ByteICMP 메시지의 타입을 나타낸다. 0: Echo Reply / 4: Source Quench / 5: Redirect / 8: Echo Request / 11: Time Exceeded
Code1ByteType별 세부적인 값을 나타낸다.
Checksum2Byte패킷의 무결성을 확인하기 위한 오류 검출(오류 보정) 값이다. 송신측에서 계산해서 보내지만, 거의 확인하지 않기 때문에 0으로 채워서 보내도 문제가 없는 경우가 많다.
Data가변ICMP를 통해 전송되는 데이터로, 보통 의미 없는 문자열(Padding)로 채워진다.

ICMP Echo Request/Reply 메시지: 송신 측의 전송 패킷이 목적지 노드나 라우터에 도착했는지를 확인하는 데 사용한다.

ICMP Destination Unreachable 메시지: 라우터가 특정 노드의 패킷을 목적지에 보내지 못할 경우 보내는 메시지로, 전송되지 못한 이유를 나타내는 정보가 포함된다.

ICMP Redirect 메시지: 라우터가 송신측 노드에 적합하지 않은 경로로 설정되어 있을 경우, 해당 노드에 최적화된 경로를 다시 지정해주는 메시지다.

ICMP Time Exceeded 메시지: 패킷이 네트워크 사이에서 무한정 돌지 않도록, 패킷을 처리할 때마다 TTL(Time To Live)을 감소시키다가 값이 0이 되면 보내는 메시지다.

ICMP Source Quench 메시지: IP 라우터의 WAN 쪽에 집중이 발생하여 송신 불능 상태가 되면 보내는 메시지로, 송신측은 이 메시지를 해석해 송신 패킷의 양을 제어한다.

실습: ping 보내고 패킷 분석하기 — 이더넷 헤더에서 MAC 주소를 확인하고, IP 헤더에서 프로토콜과 체크섬을 확인한다. ICMP 패킷은 체크섬을 0으로 채워도 문제가 없다는 점을 실제로 확인할 수 있다(예: ping ipconfig.me).

IGMP(Internet Group Management Protocol)

  • 멀티캐스트에 관여하는 프로토콜로, 멀티캐스트 그룹을 관리하는 역할을 한다.
  • 유니캐스트(Unicast): 한 호스트에서 다른 호스트로 전송하는 것
  • 브로드캐스트(Broadcast): 호스트에서 IP 네트워크에 있는 전체 호스트로 데이터를 전송하는 것
  • 멀티캐스트(Multicast): 유니캐스트와 브로드캐스트의 중간 형태로, 송신하는 하나의 호스트에 특정 호스트들을 묶어서 전송한다. 지정한 주소로 패킷을 한 번만 전달하면 멀티캐스트 그룹에 속한 모든 호스트에 전달되기 때문에 효율이 높다. IP 멀티캐스트 주소는 D 클래스 주소 대역(224.0.0.1~239.255.255.255)으로 규정되며, 일반 사용자는 볼 일이 없고 망 관리자가 라우터 설정 등에 사용한다.

네트워크 계층의 장비: 라우터

  • 네트워크의 대표적인 장비로, 게이트웨이라고도 한다.
  • 논리적으로 분리된 둘 이상의 네트워크를 연결한다.
  • 로컬 네트워크에서 브로드캐스트를 차단하여 네트워크를 분리한다.
  • 패킷의 최적 경로를 찾기 위한 라우팅 테이블을 구성한다.
  • 패킷을 목적지까지 가장 빠르게 보내는 길잡이 역할을 담당한다.

라우팅의 원리

  • route 명령으로 확인한다(윈도우: route PRINT, 리눅스(WSL): netstat -rn).
  • tracert 명령으로 목적지(예: google.com)까지 경로를 따라 ICMP 패킷을 전송해 확인할 수 있다.
  • 넷마스크 값은 제어판의 네트워크 카드에서 설정하는 서브넷 마스크 값이다.

정적 라우팅과 동적 라우팅

정적 라우팅: 관리자 권한으로 특정 경로를 통해서만 패킷이 지날 수 있도록 설정한다. 네트워크 변경사항이 발생하면 라우팅 테이블을 수동으로 직접 고쳐야 하며, 보안이 중요한 경우 선호된다.

동적 라우팅: 라우터가 네트워크 연결 상태를 스스로 파악하여 최적의 경로를 선택해 전송한다. 가까운 경로가 최적인지 돌아가더라도 빠른 경로가 최적인지는 cost를 계산해야 알 수 있으며(라우팅 알고리즘), 대표 프로토콜로 RIP(홉으로 계산)와 OSPF(시간으로 계산, RIP보다 복잡)가 있다. 네트워크 연결 형태가 변경되어도 자동으로 문제를 해결한다.

4계층: 전송 계층

대표 프로토콜은 TCP(Transmission Control Protocol)이며, TCP가 사용하는 주소를 포트(Port)라 하고 0~65535(2¹⁶-1)번까지 존재한다.

TCP(Transmission Control Protocol) 프로토콜

  • 연결 지향형 프로토콜이며, IP와 함께 통신에 반드시 필요한 가장 기본적인 프로토콜이다.
  • 특징: 높은 신뢰성, 가상 회선 연결 방식, 연결의 설정과 해제, 데이터 체크섬, 시간 초과와 재전송, 데이터 흐름 제어

TCP 패킷의 구조

  • Sequence Number: 몇 번째 패킷인지 확인
  • Acknowledge Number: 몇 번째 응답인지 확인(Sequence Number와 비슷하지만 주체가 다르다 — Seq는 보내는 쪽, Ack는 받는 쪽)
  • Checksum: 패킷이 깨졌는지 정상인지 확인. 이전 계층들에서는 0이어도 무방했지만 TCP에서는 제대로 계산해야 한다.

연결 설정 과정(Three-Way Handshaking)

  • 두 시스템이 통신하기 전, 클라이언트는 포트가 닫힌 Closed 상태이고 서버는 해당 포트로 항상 서비스를 제공할 수 있는 Listen 상태다.
  • 클라이언트가 처음 통신하려 하면 임의의 포트 번호가 클라이언트 프로그램에 할당되고, 클라이언트는 서버에 연결하고 싶다는 의사 표시로 SYN Sent 상태가 된다.
  • 클라이언트의 연결 요청을 받은 서버는 SYN Received 상태가 되고, 클라이언트에게 연결해도 좋다는 의미로 SYN+ACK 패킷을 보낸다.
  • 마지막으로 클라이언트는 서버의 응답을 확인했다는 표시로 ACK 패킷을 서버로 보낸다.

SYN: SYNchronize(동기화), ACK: ACKnowledge(인증)

연결 해제 과정

  • 통신 중에는 클라이언트와 서버 모두 Established 상태다.
  • 통신을 끊으려는 클라이언트가 서버에 FIN(FINish) 패킷을 보내고 Close Wait 상태가 된다.
  • 서버는 클라이언트의 연결 종료 요청을 확인하고 응답으로 ACK 패킷을 보낸 뒤, 서버도 연결을 종료하겠다는 의미로 FIN 패킷을 보내고 Close Wait 상태가 된다.
  • 클라이언트는 서버의 응답을 확인했다는 표시로 ACK 패킷을 서버에 보낸다.

SYN: SYNchronize, ACK: ACKnowledge, FIN: FINish

UDP(User Datagram Protocol) 프로토콜

  • 비연결 지향형 프로토콜이다.
  • 상대방이 보낸 응답을 확인하지 않아 네트워크에 부하를 주지 않는다.
  • 데이터 자체의 신뢰성이 없어 수신한 데이터의 무결성을 보장받지 못한다.
  • 특징: 비연결 지향형, 네트워크 부하 감소, 비신뢰성, 전송된 데이터의 일부가 손실될 수 있음

7계층: 응용 계층(5계층 세션 + 6계층 표현 포함)

  • FTP(File Transfer Protocol, 20, 21): 파일 전송을 위한 가장 기본적인 프로토콜. 1972년 텔넷과 함께 표준으로 제정되었으며, 클라이언트와 서버가 대화형으로 통신할 수 있다.
  • Telnet(텔넷, 23): 사용자가 원격에 있는 서버에 로그인하도록 TCP 연결을 설정한다. 단말기가 원격 컴퓨터 바로 옆에 있는 것처럼 직접 조작할 수 있게 해준다.
  • SMTP(Simple Mail Transfer Protocol, 25): 메일 서비스
  • DNS(Domain Name System, 53): 도메인 이름 주소를 통해 IP 주소를 확인할 수 있는 프로토콜
  • TFTP(Trivial File Transfer Protocol, 69): 파일을 전송하는 프로토콜. UDP 패킷을 사용하고 인증 기능을 제공하지 않는다.
  • HTTP(HyperText Transfer Protocol, 80): 인터넷을 위해 사용하는 가장 기본적인 프로토콜
  • POP3(110) & IMAP(143): POP3는 메일 서버로 전송된 메일을 확인할 때 사용하는 프로토콜이고, IMAP은 POP3와 기본적으로 같으나 메일을 읽은 후에도 메일이 서버에 남는다.
  • RPC(Remote Procedure Call, 111): 썬(Sun)의 Remote Procedure Call을 나타낸다.
  • NetBIOS(Network Basic Input/Output System, 138): 기본적인 사무기기와 윈도우 시스템 간의 파일 공유를 위한 것으로, NBT(NetBIOS over TCP) 프로토콜을 사용하여 원격 인터넷으로 전달이 가능하다.
  • SNMP(Simple Network Management Protocol, 161): 네트워크 관리와 모니터링을 위한 UDP 기반 프로토콜(SMTP와 혼동하지 않도록 주의).

L2, L3에서 패킷 흐름 이해하기

MAC 주소는 구간마다 교체되고, IP 주소는 최종 목적지까지 그대로 유지된다. 스위치는 MAC을 바꾸지 않고 전달만 하고, 라우터(게이트웨이)가 MAC을 새로 쓴다(현재 구간은 송신지 주소로, 다음 구간은 수신지 주소로 교체). 그래서 수신지 입장에서는 마지막 라우터의 MAC 주소만 확인할 수 있다.

주소역할이동 중 변화
MAC 주소바로 옆 구간(같은 네트워크 안)에서만 유효한 주소라우터를 지날 때마다 교체
IP 주소출발지부터 최종 목적지까지 쓰이는 전체 경로용 주소끝까지 유지

데이터 링크 계층(2계층) — 스위치의 동작 원리

  • 스위치는 MAC 주소만 보고 판단하는 2계층 장비다. 패킷이 흐르기 전에 송·수신 두 시스템이 서로의 MAC 주소를 알고, 스위치도 두 시스템의 MAC 주소를 알아야 한다는 것이 통신의 전제 조건이다.
  • 패킷이 흐르는 동안 스위치는 프레임 내용(IP·데이터)을 조작하지 않는다. 목적지 MAC이 연결된 포트로 그대로 흘려보내기만 한다.
  • 스위치 내부 메모리에는 포트 번호 ↔ MAC 주소 매핑 테이블이 있다(예: 2번 포트 ↔ 안방 PC MAC, 3번 포트 ↔ 작은방 PC MAC). 흔히 IP ↔ MAC 매핑으로 오해하기 쉬운데, 실제로는 포트 번호 ↔ MAC 매핑이다.
  • 스위치는 2계층 장비라서 IP 주소를 아예 모른다. 오직 "어느 포트에 어떤 MAC이 붙어 있는가"만 안다.
  • 들어온 프레임의 출발지 MAC을 보고 학습해 테이블을 채우고, 목적지 MAC이 테이블에 있으면 그 포트로만 보낸다(없으면 전 포트로 뿌린다).

네트워크 계층(3계층) — 라우터의 동작 원리

  • 스위치는 같은 네트워크(같은 LAN) 안에서만 통신을 처리하며, 다른 네트워크로 나가려면 라우터가 필요하다. 라우터가 곧 게이트웨이(내 네트워크의 출구)다.
  • 라우터는 MAC이 아니라 IP 주소를 보고 여러 네트워크를 거치는 경로를 정한다(라우팅).
  • 라우터는 프레임을 받으면 기존 MAC 헤더를 벗겨내고 새 MAC 헤더를 다시 붙여서 내보낸다.
    • 목적지 MAC → 다음 홉의 MAC으로 교체
    • 출발지 MAC → 프레임을 내보내는 라우터 자기 MAC으로 교체
    • 목적지 IP는 그대로 유지(라우터는 IP를 읽고 경로만 정할 뿐 값은 건드리지 않는다)
  • 스위치는 게이트웨이가 아니다. 게이트웨이는 라우터다.

패킷 전달 구조 — 같은 네트워크 vs 다른 네트워크

시스템이 패킷을 내보낼 때의 판단 순서는 다음과 같다.

  1. 목적지가 같은 네트워크인지 판단한다 — 자기 IP의 네트워크 부분과 목적지 IP의 네트워크 부분을 서브넷 마스크로 비교한다.
  2. 같은 네트워크라면 목적지가 같은 LAN 안에 있으므로, 목적지 MAC을 ARP로 알아내 스위치를 통해 직접 전달한다.
  3. 다른 네트워크라면 직접 갈 수 없으므로, 프레임을 게이트웨이(라우터)의 MAC 앞으로 만들어 라우터에게 넘기고, 라우터가 다음 경로로 중계한다.
구간목적지 MAC출발지 MAC목적지 IP
① 내 PC → 라우터라우터내 PC웹 서버(유지)
② 라우터 → 웹 서버웹 서버(교체)라우터(교체)웹 서버(유지)

라우터를 하나씩 거칠 때마다 목적지 MAC은 다음 홉용으로 계속 바뀌지만, 목적지 IP는 처음부터 끝까지 최종 목적지 그대로 유지된다.

참고 — 전송 계층(4계층)

  • 양 끝단(End-to-End) 간 신뢰성 있는 데이터 전송을 담당한다.
  • 대표 프로토콜 TCP는 연결 지향형으로, 흐름 제어와 에러 재전송으로 확실한 전송을 보장한다. 연결 설정은 3-way handshake(SYN → SYN+ACK → ACK)로 이루어진다.
  • UDP는 신뢰성을 보장하지 않는 대신 빠르고 가볍다(실시간·브로드캐스트 등에 유리).
  • 포트는 패킷이 시스템에 도착한 후 찾아갈 응용 프로그램으로 통하는 통로 번호다(MAC = 네트워크 카드 식별자, IP = 시스템 주소, 포트 = 응용 프로그램 통로).

최종 정리

  • 스위치(2계층): 같은 네트워크 안 → MAC을 바꾸지 않고 전달만 한다. 포트 ↔ MAC만 안다.
  • 라우터(3계층, 게이트웨이): 네트워크를 넘김 → IP는 유지하고 MAC은 다음 홉용으로 교체한다.
  • MAC은 구간마다 교체되고, IP는 끝까지 유지된다.

주소 체계와 서브넷 마스크

주소는 클래스로 나눠서 볼 줄 알아야 한다(위의 IP 클래스 표 참고).

서브넷 마스크 활용 예시

회천1동 복합청사에서 201.2.3.x 대역을 사용한다고 하자. 층마다 201.2.3.x / 201.2.4.x / 201.2.5.x처럼 대역을 다르게 쓰면 좋을까? 서브넷 마스크가 /24일 경우 가능한 호스트 개수는 254개인데, 각 층의 사람은 많아야 50명이 안 되므로 약 200개의 주소가 낭비된다.

여기서 서브넷 마스크의 활용법이 나온다. 서브넷 마스크를 /26으로 하면 201.2.3.x의 호스트 주소를 앞 2비트 기준 00 / 01 / 10 / 11로 나눌 수 있고, 각 그룹이 가질 수 있는 호스트 개수는 62개가 된다. 이제 각 층별로 하나의 그룹을 사용하면, 하나의 대역을 마치 독립된 네트워크처럼 나눠 쓸 수 있다.

라우터에는 포트별로 서브넷 마스크를 지정한다. 그러면 신호가 들어와서 특정 주소를 찾을 때, 그 주소가 어느 네트워크에 속하는지 판단할 수 있다.

서브넷 마스크는 비트맵이다

서브넷 마스크는 결국 비트맵(bit map)이고, IP 주소와 AND 연산을 해서 "이 주소가 어느 네트워크에 속하는가"를 뽑아내는 도구다.

마스크를 비트로 보면(/26 = 255.255.255.192):

11111111 . 11111111 . 11111111 . 11 000000
└──────── 네트워크(1) ────────┘  └┬┘ └─호스트(0)
                              서브넷 구분 2비트
  • 1인 자리 = 네트워크 부분(고정)
  • 0인 자리 = 호스트 부분(자유롭게 사용)

넷째 옥텟에서 앞 2비트가 층을 가른다.

비트대역네트워크 주소호스트 범위
00xxxxxx0~63201.2.3.0.1 ~ .62
01xxxxxx64~127201.2.3.64.65 ~ .126
10xxxxxx128~191201.2.3.128.129 ~ .190
11xxxxxx192~255201.2.3.192.193 ~ .254

AND 연산 예시 — 라우터에 201.2.3.70 신호가 들어오면:

IP    201.2.3.70  ->  01000110
Mask  /26         ->  11000000   (비트맵)
------------------ AND ---------
결과              ->  01000000  = 64
                     -> 네트워크 201.2.3.64 (예: 2층 대역)

라우터는 각 포트의 서브넷 마스크를 비트맵으로 써서, 들어온 주소와 AND 연산을 하여 네트워크 주소를 계산하고 어느 포트로 보낼지 판단한다. 마스크의 1 부분만 살아남고 0 부분(호스트)은 0으로 지워지므로, 개별 호스트가 무엇이든 상관없이 "소속 네트워크"만 정확히 추출된다.

핵심 한 줄: 마스크는 어느 비트가 "네트워크 이름표"인지 표시한 비트맵이고, AND는 그 이름표만 남기는 연산이다.
