리버스 프록시

리버스 프록시란?
  • 사용자는 WAS(nodejs, django, springboot, tomcat)나 DB 서버에 직접 접속하면 안 된다.
  • 앞단의 WEB서버(nginx)가 요청을 받아서 대신 넘겨주는 중계기(Proxy) 역할을 하게 됨

WEB-WAS 연동

  1. vi /etc/nginx/sites-available/default(WEB)
    server_name _;

location / {
		**proxy_pass http://192.168.6.130:8080;**
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
    • / url로 들어오는 요청을 프록시 서버가 대신 제공하도록 설정
    • tomcat 서버의 [IP 주소:포트번호] | 지시어 | 역할 | 왜 필요한가? | | --- | --- | --- | | proxy_pass | 요청을 전달할 서버 주소 지정 | WAS 서버(Tomcat)로 요청을 토스하는 핵심 설정 | | Host $host | 원래 요청의 도메인/호스트 전달 | Tomcat이 어떤 사이트에 대한 요청인지 알 수 있게 함 | | X-Real-IP $remote_addr | 실제 사용자의 IP 주소 전달 | Nginx를 거치면 WAS 입장에서 접속자 IP가 Nginx IP로 보임. 이를 실제 IP로 보정 | | X-Forwarded-For | 요청이 거쳐온 서버 목록 전달 | 여러 프록시를 거칠 경우 경유지 IP 체인을 기록 |

  3. 웹 서버의 IP 주소로 서비스 요청: 192.168.6.128/test.html

WAS-DB 연동

MariaDB

MySQL을 기반으로 만들어진 세계적인 오픈 소스 관계형 데이터베이스 관리 시스템(RDBMS) MySQL이 오라클에 인수된 뒤, 불확실한 라이선스 문제를 해결하고자 나왔다.

  • MySQL 기반이기 때문에 명령어가 mysql이다.

MariaDB 설치

  1. mariadb 설치: apt install mariadb-server -y
  2. 보안 설정 마법사 실행: mysql_secure_installation
    • 대부분의 질문에 Y | 질문 항목 | 권장 답변 | 설명 | | --- | --- | --- | | Switch to unix_socket authentication? | N | 비밀번호 방식 유지 (원격 접속을 위해) | | Change the root password? | Y | root 비밀번호를 강력한 것으로 설정 | | Remove anonymous users? | Y | 익명 사용자 삭제 → 보안 강화 | | Disallow root login remotely? | Y | 원격에서 root 직접 로그인 차단 | | Remove test database? | Y | 테스트 DB 삭제 | | Reload privilege tables now? | Y | 변경사항 즉시 반영 |
  3. root로 DB 접속: mysql -u root -p
    • DB 서버에서 접속이 잘 되는 것을 확인할 수 있다.
    • 하지만 외부 서버(WAS)에서 접속하려면 연결이 되지 않는다는 에러가 발생함.

💡DB 서버 bind address

참고 블로그 |

  • bind address: 데이터베이스 서버가 어떤 주소로의 요청을 허용할 것인지 설정하는 것
    • 보안을 위해 기본값이 127.0.0.1로 설정되어 있다.
  • 주소별 의미
    • 127.0.0.1: localhost. MariaDB가 자기 자신(localhost)에서 오는 연결만 수락
    • 0.0.0.0: 모든 IP에서 오는 연결을 수락. 외부에서 접속을 하려면 무조건 이 방식을 사용해야 함
bind address 설정 변경
  1. 현재 설정 확인: netstat -antup | grep Listen
  2. 설정 파일 수정: vi /etc/mysql/mariadb.conf.d/50-server.cnf
    • bind-address 설정을 0.0.0.0으로 수정
  3. db 재시작: systemctl restart mariadb
  4. 바뀐 설정(주소) 확인

WAS 유저 생성

  1. 데이터베이스 생성: CREATE DATABASE myapp;
  2. 유저 생성: CREATE USER 'wasuser'@'192.168.6.130' IDENTIFIED BY 'password123';
    • [유저이름]@[유저IP]
      계정 전략 보안 수준 설명
      root 계정 직접 사용 ❌ 위험 전체 DB에 무제한 접근 가능. 유출 시 치명적.
      'wasuser'@'%' (모든 IP 허용) ⚠️ 보통 어느 서버에서든 접속 가능. 권한 범위는 제한됨.
      'wasuser'@'192.168.6.130' ✅ 권장 WAS 서버 IP에서만 접속 허용. 다른 곳에서는 차단.
  3. 데이터베이스 myapp에 대한 모든 권한을 wasuser에게 부여
    • GRANT ALL PRIVILEGES ON myapp.* TO 'wasuser'@'192.168.6.130';
  4. 권한 부여한 것 실제 반영: FLUSH PRIVILEGES;
    • 권한을 부여하면 권한 테이블에 권한 데이터가 저장됨 == commit
    • 권한 테이블을 메모리에 즉시 로드하여 변경사항 반영 == push

WAS 유저로 DB에 접속

  1. MariaDB 패키지 설치: apt-get install mariadb-client-core
  2. mysql -u wasuser -p -h 192.168.6.131
    • -u: 유저명
    • -p: 비밀번호 입력
    • -h: 호스트(192.168.6.131 서버에 있는 MySQL/MariaDB에 접속)
  3. 데이터베이스 확인: show databases
